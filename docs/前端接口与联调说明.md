# 前端接口与联调说明

## 资料驱动任务 V2（2026-10-09）

学习自测、资料整编和 PPT 只采用选择资料与可选 `remarks`，主题、题数、章数、小节数及页数在全文分批读取后形成。无需 `requestVersion`，不接受非空 `topic`。所有三类任务使用当前资料执行器，升级前旧任务数据由 V23／V24 清理；视频仍使用必填主题及现行视频协议。

```json
{"taskType":"QUIZ_GENERATION","documentIds":[101,102],"remarks":"面向初学者，重点检验概念应用"}
```

```json
{"taskType":"KNOWLEDGE_COMPILATION","documentIds":[101,102]}
```

```json
{"taskType":"NOTES_PPT","documentIds":[101,102],"remarks":"用于课堂讲解","presentationOptions":{"pageCount":0,"themeId":"default","maximumAmount":10,"imagePolicy":"CONCEPT"}}
```

`remarks` 省略、null、空字符串、纯空白统一为无特殊要求，非空去除首尾空白，上限 1000 字符。资料仍为 1～6 个授权文档，`scope` 默认为本人。学习默认 `FIXED`；PPT 可省略 strategy，服务端统一采用固定阶段和动态并行节点。

| V2 选项 | 自动模式及显式要求 |
|---|---|
| 自测 | 整个 quizOptions 省略时 questionCount=0、两种题型、MEDIUM；0 表示自动，显式正数为数量要求，最大 512 |
| 整编 | 整个 compilationOptions 省略时 DETAILED、maximumChapters=0；0 表示自动，显式正数为章节上限，最大 512 |
| PPT | pageCount 省略或 0 表示自动；显式 2～512 为含来源页的总页数要求；省略整个选项时 default/MIXED、费用上限 30 元，付费操作仍需本人审批 |

显式学习 options 对象仍须提供合法的题型／难度或详略字段。备注中的精确题数／章数／PPT 总页数要求会被解释并核验，不能满足时返回任务错误 `WORKFLOW_REQUIREMENTS_UNSATISFIED`，不会发布不同数量冒充满足。

新增 `GET /api/v1/tasks/{id}/content-plan`：尚未固化时 204，固化后返回 `{plan,planHash,completedUnits,fullSourceRead}`，均 no-store、仅本人可读。内容统一使用扩容后的 UTF-8 字节限制，PPT 编辑采用同一规则；无旧任务或版本选择兼容。V24 清理升级前的三类内容任务，旧任务 ID 返回不存在。`plan` 包含资料归纳标题、主题集合、已理解的要求、数量理由、稳定目标、事实映射、遗漏及原因、资源估计；`counts` 的 questions/chapters/sections/contentSlides/sourceSlides/totalSlides 来自目标数组。完成节点进度可在阶段内部增长，不能把阶段百分比当时间估计。原 `/plan` 继续查询旧执行计划。

学习成功结果保留原 JSON 字段并增加 `contentPlan`；Markdown 也展示数量和选材说明。`fullSourceRead=true` 表示完整读取所选原文，不保证模型提取每条知识，也不等于全部知识都出过题。V2 PPT 预览增加 `contentPlan={planHash,title,contentSlides,sourceSlides,totalSlides}`，来源页每页最多 12 条、双栏展示，完整出处保留在备注。编辑可提交最多 512 个单位，但必须保持批准前的实际数量、ID、顺序和素材模式；不能借编辑变更内容计划数量。新版预览摘要包含内容计划，编辑后重新审批。

默认资料策略为原文合计 1,000,000 UTF-8 字节、每批 3000 字节、4096 条事实、256 个产出目标、最多 4 个并行工作线程。它们是服务端创建时快照的资源保护上限，不是固定产出数量。来源闭包最多 32 项、每份 PPT 最多 8 张图、原有金额与词元账本上限继续生效；原文上限不等于保证该体量能在所有费用／模型配置下完成。超过资源时明确失败，不截断或自动扩大费用。旧 24000 字节、6 章、12 页限制已移除。

新增可解释失败包括 `WORKFLOW_PLAN_BUDGET_EXCEEDED`、`WORKFLOW_UNIT_TOO_LARGE`、`WORKFLOW_INDEX_CAPACITY_EXCEEDED`、`WORKFLOW_EXTRACTION_CAPACITY_EXCEEDED`；均需调整范围、要求或服务器资源，不自动重复创建付费任务。来源正文、处理代次或权限变化仍阻止恢复和发布。

三个资料工作流只支持本文现行协议，旧执行入口及历史计划接口已删除。

更新日期：**2026-10-09**。适用于当前 Novid 后端源码，供前端开发与联调使用。实际目录为 `docs/`，本文是现行接口说明；历史改造过程和测试证据见[测试验证与验收报告](temp/测试验证与验收报告.md)，环境配置见[部署配置与运行维护](部署配置与运行维护.md)。

## 2. 接入约定

### 2.1 地址、认证与响应

- 业务 API 前缀：`/api/v1`。默认后端地址为 `http://localhost:8080`，实际端口以启动配置为准。
- 仅 `POST /api/v1/auth/login` 与 `GET /actuator/health` 无需认证。健康检查地址不在 `/api/v1` 下；健康成功不保证模型、ES、Worker 全部可用。
- 认证头：`Authorization: Bearer <token>`。token 是不透明随机值，不是 JWT；不通过 Cookie、URL 参数或请求正文传递。
- 每次正式 API 请求返回服务端生成的 `X-Request-Id` UUID 响应头；SSE 取初始响应的该头。客户端传同名头不能指定后端日志编号。报错反馈保留该编号，排查方式见[日志记录与问题排查](日志记录与问题排查.md)。
- JSON 使用 camelCase。成功直接返回对象或数组，**没有** `{code,data}` 包装。
- 成功状态见第 4 节：一般 void 接口为 **200 空正文**，上传／任务创建／PPT 导出登记为 202，会话创建为 201，会话删除和媒体人工验收为 204。未就绪预览／检查／计划也可返回 204。空响应不得直接调用 `response.json()`。
- 时间字段是 ISO-8601 UTC 字符串，如 `2026-10-03T08:00:00Z`；前端转换为用户时区展示。
- 数值 ID 当前以 JSON number 返回。Java long 若将来超过 JavaScript 安全整数范围，需要协调后端改为字符串，不能在已发生精度丢失后用 `String(id)` 补救。字符串 ID 如 traceId、approvalId、sectionId、chunkId 保持原样。
- 未知 JSON 字段会被拒绝。不要把整个响应对象原样作为 PATCH 请求，也不要附加 userId、requesterUserId、modelId、endpoint、密钥、预算等字段。`ownerUserId` 仅能用于下文明确列出的范围筛选，不用于指定新资源归属。

### 2.2 同源与开发代理

当前后端不开放跨域 CORS。开发服务器应把浏览器同源的 `/api` 请求代理到后端；如需健康检查，一并代理 `/actuator/health`。部署也采用同域反向代理。代理须传递 Authorization、multipart 请求体与 SSE 响应，SSE 路径关闭响应缓冲并允许足够的响应等待时间。

不要把浏览器跨域预检失败当成登录或模型故障。MySQL、ES、模型地址与凭证全部留在后端；前端只配置 API 地址。

### 2.3 分页、列表与版本

分页参数 `page` 从 **0** 开始，范围 0～10000；`size` 默认 20，范围 1～100。会话消息使用非负 `afterSeq` 游标，默认 0、按 seq 升序读取大于该序号的事件。返回裸数组，没有 total／hasNext／totalPages。

文档列表先分页，再过滤来源已经无权读取的文档，因此中间页也可能不足 size 甚至为空。不要以“返回不足一页”作为可靠的最后一页依据；界面可以提供明确的上一页／下一页，当前后端不支持精确总页数。

| 版本字段 | 用途 | 前端提交位置 |
|---|---|---|
| 知识库 `version` | 编辑和删除冲突检查 | PATCH 正文／DELETE 查询参数 |
| 文档 `documentVersion` | 原文内容版本 | PATCH 正文／DELETE 查询参数 |
| 文档 `activeProcessingRevision` | 当前内容版本的已激活索引代次，可为 null | 展示、判断索引激活变化；不由客户端指定 |
| 记忆 `version` | 修改和删除冲突检查 | PATCH 正文／DELETE 查询参数 |
| 任务 `stateVersion` | 状态变化序号 | 仅展示／比较；actions 不接收该字段 |
| 会话 `version` | 关联问答和删除的冲突检查 | chat 正文 `sessionVersion`／DELETE 查询参数 `version` |

修改后使用响应中的新版本覆盖本地状态。409 时重新查询、让用户核对后重试，不自动覆盖。记忆的版本不匹配当前返回 403，不能统一当作 409。

### 2.4 幂等键与重复提交

文档上传、任务创建和 会话创建必须带 `Idempotency-Key`，格式为 `[A-Za-z0-9_.:-]{1,128}`。建议使用 `crypto.randomUUID()`。网络结果不确定时创建操作用**同一个键和同一组参数**重试；用户改变文件、目标、标题、主题、范围或文档集合时生成新键。

同用户、同 API、同键同参数返回既有资源；同键不同参数为 409 OPERATION_CONFLICT。不同 API 的键空间独立。后端保留去重记录至少七天，当前未自动清理，不承诺无限期 exactly-once。

其他创建接口（知识库、记忆、notes/prepare）不具备上述键去重。reprocess／retry每次登记新代次，不能自动重复发送；recover只提前调度指定失败代次，不重置预算或创建代次。task actions 也不是幂等设置：重复 pause／resume／cancel 可能为 409；网络中断后先查任务状态。

## 3. 登录、角色与资料范围

### 3.1 登录流程

1. 登录，保存返回的 token、expiresAt 和 user。没有默认教学账号或公开注册接口；由管理员提供账号，测试时的随机账号已清理。
2. `user.passwordChangeRequired=true` 时只进入改密流程。此时仅可调用 me、password、logout；业务接口为 403 PASSWORD_CHANGE_REQUIRED。
3. 改密成功后**当前及其他旧 token 全部失效**，清理本地登录状态，重新登录。
4. 页面恢复时通过 me 核验身份。令牌有效期八小时；没有 refresh token／续期接口。
5. 退出时撤销当前 token，并清除本地状态。禁用、角色调整、密码变更都会使已有登录失效。

用户名为 3～64 个 `A-Za-z0-9_.-` 字符。新密码为 12～64 个 Java／JS UTF-16 单元，且不超过 **72 个 UTF-8 字节**；中文密码也须检查字节长度。登录密码最多 72 UTF-8 字节。除正文码点上限外，文档中的字符长度限制按 Java String 长度理解，可用 JavaScript `.length` 对应；UTF-8 字节用 `new TextEncoder().encode(value).length`。

业务请求 401 通常需清除登录并引导重新登录；登录 401 应提示凭证错误。**改密时原密码错误也会返回 401**，不要立即断言当前 token 已失效，可调用 me 复核。登录按账号有五分钟窗口限流，连续登录请求可能触发 429，避免自动反复重新登录。

### 3.2 权限矩阵

| 操作 | USER | ADMIN |
|---|---|---|
| 读取／检索知识资料 | 本人启用且未删除的库 | 默认 SELF，可显式 ALL／SELECTED 读取他人启用库 |
| 创建、编辑、上传、修订、删除知识资料 | 本人资源 | 仍限本人资源 |
| 读取本人禁用库元数据、重新启用库 | 允许，需已知库 ID | 同样仅本人 |
| 删除禁用库中的本人文档／来源撤销的本人笔记 | 允许，需已知 ID 和文档版本 | 无他人写入旁路 |
| 偏好、确认、任务、报告、运行摘要 | 仅本人 | 同样仅本人 |
| 会话列表、详情、历史、关联问答、版本删除 | 仅本人 | 同样仅本人，无跨用户读取或修改旁路 |
| 入库管理状态、recover／retry／reprocess | 仅本人 | 同样仅本人；知识跨库只读不授予处理预算读取或管理权 |
| 用户管理 | 不允许 | 允许；最后有效 ADMIN 不可禁用或降级 |

禁用库不出现在知识库列表，文档读取／检索也受阻；owner 仍可通过已知 ID 读取库元数据并重新启用。目前没有“包含禁用库”的管理列表或禁用库文档列表参数。禁用操作前应保留库 ID 或提供已知 ID 的恢复入口；不能假设刷新列表后仍能找回全部禁用库。

按钮展示可依据 `user.role`、资源 `ownerUserId` 与 `user.id`；最终权限由每次后端请求决定。知道 ID 不等于可以读取，不存在与无权资源通常都返回 403，不应据此猜测他人数据是否存在。

### 3.3 资料范围的两种传递形式

问答和任务 JSON 使用 `scope` 对象：

```json
{"mode":"SELECTED","knowledgeBaseIds":[12,18],"ownerUserId":null}
```

知识库／文档列表使用查询参数：

```text
GET /api/v1/documents?scopeMode=SELECTED&knowledgeBaseIds=12,18&page=0&size=20
GET /api/v1/knowledge-bases?scopeMode=ALL&ownerUserId=7&page=0&size=20
```

- SELF 默认本人；knowledgeBaseIds 应为空，ownerUserId 省略或为本人。
- SELECTED 最多 100 个正数库 ID，空数组表示**零范围**。包含越权或禁用库时整体拒绝，不会静默过滤其中几个 ID。
- ALL 仅 ADMIN；knowledgeBaseIds 必须为空。ownerUserId 可进一步筛选某个用户的知识库，但不能把 SELF 变为其他用户范围。
- `GET /knowledge/statistics` 仅接收 scopeMode、knowledgeBaseIds，不支持 ownerUserId 筛选；问答和任务的 scope 支持该字段。
- 私人资源读取接口不接受 scope 来扩大范围。会话关联 chat 可以显式提交知识 scope；省略时继承会话已保存范围，旧单轮 chat 省略时使用 SELF。前端缓存按用户及完整范围隔离；切换账号、范围或遇到授权撤销时清理相关内容。

## 4. 全部已实现 HTTP 接口

下表路径均相对 `/api/v1`；标有空的响应为 200 空正文。字段类型见第 5 节。PATCH 不是任意字段局部更新，应只发送表中列出的字段；boolean 字段显式发送 true／false，避免缺省被解析为 false。

### 4.1 账户

### 5.5 常见字段解释

这些枚举描述当前实现。遇到未来未知状态时显示原状态或“未知状态”，停用可能有副作用的按钮，不自动当作成功。

上传 202 示例：

```json
{
  "id": 101, "knowledgeBaseId": 12, "ownerUserId": 7,
  "title": "学习笔记.md", "format": "md", "documentVersion": 1,
  "ingestionStatus": "RECEIVED", "activeProcessingRevision": null
}
```

`GET /documents/101` 的外层是 `{document,text,sourceDependencies}`，不是 DocumentSnapshot 本身。format 是文档存储格式，title 是标题／上传文件名；没有文件大小、上传时间、generated 或处理百分比字段；最新处理错误和配置事实通过独立 ingestion 接口读取。

AiResult 的 SUCCESS 表示服务端生成并校验了回答，NEEDS_INPUT 表示当前范围没有可用证据，是正常 200 而非请求失败。会话关联结果的 sessionId/sessionVersion 为已提交会话及新版本；旧单轮结果两字段均为 null。SUCCESS 及 SQL 提交不证明浏览器已收到答案，SSE 还需正常 EOF。当前失败通常通过非 2xx JSON 或 SSE error 交付，不返回 `AiResult.status=FAILED`。mock=true 显示测试结果标识；modelId 是后端内部目标 ID，如 primary／program／none，不一定是供应商模型名称。程序统计可为 mock=false、modelAttempts=0、无 citations。

旧问答只有USER／ASSISTANT；工具成功续轮按USER、成对TOOL_REQUEST／TOOL_RESULT、ASSISTANT原子保存，工具事件保留toolCallId/toolName。失败、取消与不完整配对不保存草稿。消息 sourceReferences 保存版本化来源及可空位置，offset 仍为 UTF-16 起含终不含；历史全文下载仍未开放；当前版本／代次的章节分页与块映射不能替代版本不一致的旧历史定位。

运行摘要包含执行关联与完整性字段；具体节点、用量和有界内容快照由 `/runs/{id}/graph` 返回，不能只用摘要绘制图。摘要不包含正文；已绑定来源的工作流节点可以返回输入／输出快照，价格金额仍单独查询费用接口。失败响应仍不保证带traceId，可从本人列表定位失败运行。

## 6. 页面流程与状态处理

### 6.1 上传、修订与索引

1. 用户选择本人启用库与文件，完成大小／扩展名检查并生成幂等键。
2. 上传得到 202 后展示“资料已登记，索引尚未就绪”，保存 DocumentSnapshot。
3. 建议每 2～3 秒查询已知文档详情，适当退避；页面退出或无登录时停止轮询。等待过久提示“处理尚未完成”，不擅自把文档变为失败。
4. `ingestionStatus=READY` 且 activeProcessingRevision 非 null 后，展示目录／小片并可用于检索。无激活代次时 sections／chunks 为 409 INDEX_NOT_READY。
5. FAILED 时可查询 ingestion.errorCode 并展示重处理按钮；status/errorCode 描述最新处理意图，不等同当前仍可用的 activeProcessingRevision。

**对外文档状态不是内部任务状态。** 内部领取会进入 PROCESSING，但 DocumentSnapshot 当前不暴露该变化；新上传可能一直显示 RECEIVED，直到 READY 或 FAILED。不要要求从详情先读到 PROCESSING 才允许进入 READY。

修订内容使 documentVersion 增加、新版本登记索引；旧版本的目录／引用不能直接套用到新正文。retry 与 reprocess 当前行为相同：创建新 processing revision，不改变 documentVersion。

重处理已 READY 的文档时，旧激活索引可继续可用，状态仍可为 READY。请求前记录 activeProcessingRevision，之后观察它增大才可确认新代次激活；新代次失败时旧 READY 仍可能保留。可通过 ingestion 查看最新 processingRevision/status/errorCode/configHash/expectedChunkCount 和当前 activeProcessingRevision。只有最新意图 READY 且与 active 相同才说明该意图已激活；旧 READY 可继续存在。expectedChunkCount 是解析预期总数，不是已完成百分比。旧批次的解析／映射／计数器版本为 null，不伪造回填。

删除或禁用先在权威数据中生效；ES 清理由后台队列完成，界面按 API 成功更新资源即可，不等待 ES 物理删除。禁用库正文和文档列表不可读，删除本人文档可以按之前获得的 ID 与 documentVersion 调用；需要重新查询正文时先恢复库权限。

#### 入库逐批状态与恢复

`GET /api/v1/documents/{id}/ingestion` 保留原最新意图／active字段，追加progress。本接口仅本人可读，ADMIN读取他人入库事实也是403；合法跨库正文、目录、章节、小片仍可只读。返回不包含向量、批次输入、摘要、worker或凭证。旧Java构造入口仍可令progress为空；旧READY记录的phase为LEGACY、期限为空、批次计数为零，不能补称已逐批核验。

外层status仍为RECEIVED／PROCESSING／FAILED／READY，phase指出实际步骤。失败时展示errorCode、failureStage和计数；embeddedBatches含已生成且INDEXED的批次。indexedBatches只计搜索核验后的持久事实，尚未通过最终全集检查时不能据此展示READY。peakVectorItems是单批向量项数，不是整个进程堆或常驻内存。unknownBatches包括发送中与未知结果，不自动重试模型。

reservedInputTokens为每次发送前预留的UTF-8字节保守上界，actualInputTokens只加提供方已返回的输入Token；unknownUsageAttempts记录无可靠用量的尝试，成功但缺usage也算未知，不能把已知部分当完整费用。迟到结果只可补其原尝试用量，不能激活旧租约。价格与费用事实另查 `/ingestions/{ingestionId}/fees`，见第 12 节。

单代次32项／16000保守词元每批、5000片、累计160次真实尝试／2500000保守输入预留、三次领取；首次领取确定十分钟绝对deadline，停机和等待也消耗期限，重启不延长。模型SDK重试为零。ES失败自动等待30秒后在剩余预算内恢复。

本人选择提前恢复时发送 `POST /api/v1/documents/101/index-actions?action=recover&processingRevision=2`，成功200空正文；只更改nextAttemptAt，响应不是入库成功，也不会绕过关闭的Worker。必须是当前内容最新意图、FAILED、可恢复、未耗尽且无未知向量；缺代次400，旧代次／耗尽／未知为409 INGESTION_RECOVERY_CONFLICT，越权403。recover可重复提前调度仍失败的同代次；已领取／READY后409，网络中断先查询状态。

EMBEDDING_RESULT_UNKNOWN表示已登记发送但没有完整持久向量，提供方没有可用结果查询／幂等生成协议，因此停止自动生成，费用可能发生。用户明确选择retry或reprocess会创建全新代次及预算，可能再次收费；两个旧动作不能作为recover的自动替代，不能声明外部严格一次。INGESTION_PLAN_CONFLICT表示输入／配置变化或持久事实不符，新代次须由用户明确发起。INGESTION_BUDGET_EXCEEDED表示硬额度或期限耗尽。上述冲突均409且HTTP错误retryable=false；仅progress.retryable表示当前失败代次可提前恢复。

### 6.2 引用与原文定位

回答中的 `[E1]` 对应 citations 的 evidenceId。展示标题、库 ID、documentVersion、headingPath 与原文范围；matchedChunkIds 是召回小片，includedChunkIds 是实际交付上下文，后者可能更多。citations 是交付给模型的证据集合，不保证每一项都被答案文本引用。

offset 为 Java／JavaScript **UTF-16 索引，起点包含、终点不包含**，原文范围可用 `text.slice(startOffset,endOffset)`。用 DocumentContent.text 的原始内容定位，不在渲染后的 Markdown HTML、重新规范化换行的文本或不同内容版本中套用 offset。

当前文档详情和 source 下载始终返回当前版本，没有历史版本读取参数。证据版本与当前版本不同时，展示证据自身的 text 和版本标识，提示原文已更新；不要假设 `?documentVersion=1` 能取历史内容或在新正文上高亮旧位置。章／片 ID 是不透明字符串，目录可以用 parentSectionId 建树，但加载分页目录后再整合。

章节详情请求示例：`GET /api/v1/documents/101/sections/d101v1r1s1?documentVersion=1&processingRevision=1&maxTokens=300`。sectionId 必须取目录实际值；afterOffset 省略时从该章节起点开始，后续原样传 nextOffset。maxTokens 为 4～当前服务端 maxEvidenceTokens（最高4000）的保守输入额度，不是字符数。页含子章节，覆盖 [sectionStartOffset,sectionEndOffset)；complete=true 且 nextOffset=null 才读完。游标是绝对 UTF-16 下标，不能相加或用页号推算。无版本／代次为400；非当前版本／代次为409 CONTEXT_VERSION_CONFLICT；跨批次 sectionId 为400 CONTEXT_MAPPING_INVALID；非法／半代理对游标为400；未激活为409 INDEX_NOT_READY；无权限为403。分页期间版本变化时刷新文档和目录，从新范围重新开始。响应无内部文件路径。

ChunkSnapshot.sourceMap 的 embedding 范围对应原文 source 范围，二者都是 UTF-16 起含终不含；行号一基、endLine 包含末行。blockId 关联超长代码／表格的各 partIndex；MIXED 通过每个映射段区分关联块。标题前缀没有正文映射；repeatedHeader=true 指真实原始表头的重复输入，不能把重复字串当新原文。可容纳行组完整保留，超长单行／代码／表头仍按安全码点拆，不越过硬额度；过长表头无法重复时仍保存完整原文和块关联。旧批次 blockType=LEGACY、sourceMap=[]，需 owner 明确 reprocess 才生成新映射。RAG 跨父段表头可作为独立连续原文 EvidenceBundle 提供，matched=[]、included 为真实表头片，保持原 Citation 和 会话位置契约。

媒体及历史 Markdown 使用 `[D101v1]` 形式的版本引用。新学习结果通过 `/tasks/{id}/result` 提供结构化 citations，不能把旧报告引用套用到当前版本。

### 6.3 保存 AI 笔记的确认流程

1. 从回答 citations 的 document 元信息取得真实 SourceDependency，按 documentId＋documentVersion 去重，保留全部实际使用来源；无来源的程序统计不能直接走这个笔记接口。
2. 用户选择**本人启用**目标库，核对 title、content 和来源，调用 notes/prepare。
3. 展示 ApprovalSnapshot 完整预览；GET approvals/{id} 可重新核验来源。prepare 只创建确认记录，不代表笔记保存成功。
4. 用户批准时只发送 `{ "approved": true }`；拒绝发送 false。确认接口不接收修改后的内容、目标、operationId 等字段。
5. 只有响应 status=APPROVED 且 documentId 非 null 才展示保存成功；新笔记也需要索引，不能立即宣称可检索。

示例 prepare：

```json
{
  "knowledgeBaseId": 12,
  "title": "本次问答总结",
  "content": "根据资料整理的笔记正文。",
  "sourceDependencies": [{"knowledgeBaseId":12,"documentId":101,"documentVersion":1}]
}
```

确认期限 30 分钟。WAITING／APPROVED／REJECTED 是当前存储状态；过期不会保证自动变成 EXPIRED，界面依据 expiresAt 展示倒计时，最终以后端 410 为准。目标库 version 变化或来源／权限变化会使确认无效，需要重新准备；修改预览内容也必须生成新确认记录。服务端会展开派生来源，返回列表可能不同于提交列表，应展示返回的完整来源。

重复批准已成功的同一确认会返回既有事实并重新核验来源，不创建第二份笔记；拒绝已批准的确认、再次处理已拒绝记录会冲突。不要复用 prepare 来模拟批准重试，更不能在客户端移除来源约束。

### 6.4 学习任务

选择 1～6 份授权资料，可填写 `remarks`，不填写主题。数量选项缺省或为 0 时自动规划；题型、难度和详略可以选择。客户端不指定子工作节点数量。后台按准备、提取、组织、生成、质检、发布六阶段执行，完整来源读取后接受不可变内容计划。

```json
{"taskType":"QUIZ_GENERATION","documentIds":[101,102],"remarks":"重点检验概念应用"}
```

```json
{"taskType":"KNOWLEDGE_COMPILATION","documentIds":[101,102,103],"compilationOptions":{"detailLevel":"DETAILED","maximumChapters":0}}
```

默认原文合计上限 1,000,000 UTF-8 字节，其他资源来自任务创建时的服务器策略；超出父预算明确失败。原文读取、模型提取和人工质量验收分别记录。通过 `/content-plan` 展示资料推导的题数、章节／小节数和规划理由，通过 `/result` 读取已发布的私人学习 JSON，使用 artifactId 下载 Markdown。答案与解析属于本人学习资料，前端不将其当作考试保密数据。

空或未入库资料、来源变化、计划无法满足要求及资源不足均按真实错误处理；202 仅登记任务，未发布结果返回 409。暂停、恢复和取消不重置额度。已删除的旧任务返回无访问权限，不提供旧协议恢复入口。

### 6.5 联调环境与轮询

联调前由后端负责人确认账号、数据库迁移、知识索引、SEARCH_ENABLED、入库／任务／媒体 Worker、模型和媒体能力配置。配置变更须重启后端；前端没有修改开关、初始化索引或直接触发后台批次的 API。

以当前响应的 `progress.workerEnabled/executionActive/stage` 判断执行事实；不要将仓库默认值或历史 `.env` 记录当作当前进程状态。任务进度为空时显示“进度暂不可用”，仍以任务顶层 status 为准。按 `pollAfterMillis>0` 轮询，为 0 则停止自动轮询并提供手动刷新；操作成功后重新查询，页面离开、退出或切换账户时取消前端请求。

创建响应的 `Retry-After: 2` 单位是秒，`pollAfterMillis` 单位是毫秒。worker 关闭时 `WAITING_FOR_WORKER` 不是失败；等待超时不修改服务端状态、不自动重复创建任务。媒体开关与普通学习任务开关分别由后端配置。

### 6.6 本人多轮会话与失败恢复

1. 新会话调用 POST sessions，提交 title 及新的幂等键，保存返回 id/version。已有会话通过列表和详情恢复；退出或换账号清除本地会话正文和状态。
2. chat／stream 同时提交 sessionId/sessionVersion。省略 scope 继承已保存范围；显式 scope 改变时重建合法模型上下文，不沿用旧范围历史或派生摘要。
3. 成功得到 AiResult（或 SSE done 并正常 EOF）后使用 sessionVersion 覆盖本地版本。程序统计和 NEEDS_INPUT 同样保存带实际状态的问答对，不能把 NEEDS_INPUT 展示成有证据回答。
4. messages 用 afterSeq=0 开始，后续提交最后一条 seq；每条 USER 和 ASSISTANT 都占一个序号，不将事件数当作问答轮数。RESTRICTED 用“历史内容当前不可访问”占位，不能复用之前缓存的正文或来源。
5. 409、超时、取消或网络结果不确定时先读详情和消息。成功提交和失败释放执行权都会推进 version；不要用旧版本自动重问，更不要把刷新版本当作允许重复付费调用。
6. 删除时提交最新 version，204 后清除本地历史。删除不会清除显式保存的偏好；偏好仍通过 memories 本人接口独立管理。

创建及首轮示例（ID/版本以返回值替换）：

```json
{"title":"备份规则学习"}
```

```json
{"question":"解释第二篇资料的备份策略","scope":{"mode":"SELECTED","knowledgeBaseIds":[12],"ownerUserId":null},"sessionId":701,"sessionVersion":1}
```

下一轮使用上次返回的新版本，并省略 scope 继承该范围：

```json
{"question":"再解释刚才第二篇资料","sessionId":701,"sessionVersion":2}
```

完整历史保存与模型窗口独立：默认模型窗口最多 12 条事件／8000 UTF-8 字节，摘要最多 2000 字节，总历史输入最多 12000 字节。摘要经同一网关生成并带覆盖序号和来源，不作为私人资料接口输出；摘要与回答共用在线 60 秒、10 次尝试、6 轮及 8 次工具预算，不因摘要重置。回答持久化上限为 64 KB；达到会话／消息配额或预算时真实拒绝。长期偏好只通过用户明确保存更新，资料内容和摘要不会自动改写偏好。

### 6.7 模型逻辑选择、主备和结构化回答

`POST /chat` 与 `/chat/stream` 支持可选 `modelProfile`、`responseFormat`。省略逻辑选项走AUTO；当前服务端白名单knowledge／economy／analysis／report，显式选项走PROFILE，仍合并KNOWLEDGE_QA硬条件。所有身份使用相同白名单，不接受modelId、真实名称、endpoint、密钥、任意Schema或预算。EXACT只供服务端批准入口；统计和无证据NEEDS_INPUT不产生聊天路由。

```json
{"question":"每周几备份？","modelProfile":"knowledge","responseFormat":"STRUCTURED"}
```

responseFormat只能TEXT或STRUCTURED，默认TEXT。STRUCTURED在模型内部要求固定status／answer／references，程序校验字段、枚举、重复字段、尾随JSON、引用及状态语义，最终仍返回既有AiResult.answer正文和citations，不发内部JSON或SDK消息。信息不足为正常NEEDS_INPUT；非法结构最多修复一次，失败结束，拒绝／截断不修复。旧单轮、会话和SSE事件顺序不变。

AiResult.route为可空脱敏快照：策略／质量配置版本、profile、routingMode、selectedModelId、selectionReason、剩余合法fallbackCandidates及本逻辑调用失败／备用／修复attempts；会话提交也保留返回字段。qualityVersion=configured-baseline-unverified-v1只表示配置，非完整选型认证。reservedInputTokens为保守上界，不等于PROVIDER用量，UNKNOWN用量／价格不当免费。route只在本次响应／执行内存，`/runs`和历史消息没有新增持久路由或Token明细接口。

备用每次重核身份、会话与原来源，按目标窗口先去掉较早完整轮次／摘要，再去掉末尾完整证据包；系统规则、当前问题和必要证据不截断，不足失败。citations只列最后目标实际收到的包。摘要与报告重试／备用也重核来源，固定输入不足明确失败，不假称完整页仍已覆盖。全文校验前不发草稿，主备不拼答案或重放写入。

新增错误：MODEL_SELECTION_DENIED（400，未批准选项）；MODEL_CONTEXT_INSUFFICIENT／MODEL_CONTEXT_NOT_PORTABLE（400，窗口／工具协议不可安全切换）；MODEL_TRUNCATED／MODEL_REFUSED／MODEL_TOOL_CALL_PENDING（400，截断／拒绝／非工具模式不接受工具申请）；MODEL_STRUCTURED_INVALID／MODEL_REPAIR_EXHAUSTED（400，结构／一次修复约束失败）；MODEL_RATE_LIMITED（429）；MODEL_CONFIGURATION_ERROR（503，修正配置并重启，retryable=false）。NO_COMPATIBLE_FALLBACK仍503。同步JSON失败非2xx；SSE开始后的白名单／模型失败发error且无done。retryable不授权自动付费重试，提供方正文／地址／认证头不返回。真实双目标状态以验收报告为准，本机协议通过不能标真实主备已验收。

### 6.8 内容计划查询

`GET /api/v1/tasks/{id}/content-plan` 返回本人已接受的 ContentWorkflow.Snapshot；尚未规划返回 204/no-store。返回计划摘要、主题、要求、目标、遗漏原因、数量及完成目标数量。查询不触发模型生成或恢复。`/tasks/{id}/plan` 已删除，不应继续请求。

### 6.9 PPT／视频共用的预览与审批

1. 使用 `POST /tasks` 和新幂等键登记任务；PPT 省略 strategy 或传 FIXED，视频省略或传 PLANNED。202 仅表示排队，后端会校验媒体能力、资料、预算和选项。
2. 轮询任务，并查询 `/preview`；204 表示当前无预览，暂不解析 JSON。200 后展示完整 units、sourceDependencies、coverage、费用、有效期、素材和视频分镜。
3. 修改时 PATCH `{previewVersion,units}`，只发送允许字段，保留全部原单位、unitId、imageMode、seconds 与合法 references。版本变化后替换本地预览、清旧文件缓存、重新批准。
4. 用户核对当前预览后向 `/media/approvals/{approvalId}/decision` 提交 `{approved:true,taskId}`；拒绝用 false。批准返回 MediaPreview，不代表已经生成最终文件，之后继续查任务和原操作状态。
5. `WAITING_MEDIA_REVIEW` 时获取认证候选附件并进行看图／听看。提交 `{previewVersion,accepted,note}` 到 `/media-review`，204 后重查任务；接受为 SUCCEEDED，拒绝为 PAUSED。人工验收不授权新的购买。

媒体预览编辑限制：title 非空白、最多 200；text 最多 3000、PPT 不得空白，视频台词另限 1024 Unicode 码点；notes 最多 1500；imagePrompt 最多 1000；references 不得为空且必须来自原来源。WEB_SEARCH 的 imagePrompt 不能修改；imageMode／seconds 不能更换。PPT 支持 TITLE／TEXT／TWO_COLUMN／IMAGE_TEXT，SCENE 用于视频。编辑不接收直接修改 Storyboard、来源、目录、资产、报价、配置摘要或提供方 ID。

预览状态 WAITING／APPROVED／REJECTED、顶层任务状态、media-operations.state 是三类不同状态。版本上限、当前状态或在途外部操作可能阻止编辑；`PREVIEW_CHANGED` 后重读当前预览，不能沿用旧 approvalId。审批有效期通常 30 分钟，预算和任务截止仍独立受限。

生成前拒绝会使预览 REJECTED、任务 CANCELLED；生成后人工拒绝则使任务 PAUSED。人工验收阶段通过 progress.stage 展示 `HUMAN_ACCEPTED`／`HUMAN_REJECTED`，前端以任务 status 判断结果，不将阶段字符串作为错误码。

| 任务状态 | 页面行为 |
|---|---|
| QUEUED／RUNNING | 展示真实阶段，按 pollAfterMillis 轮询；允许 pause／cancel |
| WAITING_APPROVAL | 展示当前预览，等待用户批准／拒绝；可 cancel，不调用 resume 代替批准 |
| WAITING_EXTERNAL | 展示原操作及下次查询时间；可 pause／cancel，读取 API 不触发外部查询 |
| NEEDS_RECONCILIATION | 停止自动重购，展示 errorCode；有原 ID 的恢复由后端守卫处理，无 ID 未知提交禁止恢复购买 |
| MEDIA_READY | PPT 素材就绪，尚未导出／人工验收；按条件提供 presentation-export |
| WAITING_MEDIA_REVIEW | 可下载本人候选，提供接受／拒绝；不显示最终成功或 100% |
| PAUSED | 手动恢复／按允许状态编辑；拒绝的旧候选不可继续读取 |
| FAILED | 展示错误；媒体允许受限手动 resume，未知提交和耗尽预算不能绕过 |
| SUCCEEDED | 已经本人接受，停止轮询；PPT 后续编辑会撤回旧文件并要求重新批准 |
| CANCELLED | 停止轮询、清私人候选缓存；取消不代表提供方停止或退款 |

`pause` 仅允许 QUEUED／RUNNING／WAITING_EXTERNAL；学习 resume 仅允许 PAUSED，媒体另外允许 FAILED／NEEDS_RECONCILIATION，但无原 ID 未知提交返回 `MEDIA_SUBMISSION_UNKNOWN`。终态 SUCCEEDED／PARTIAL／FAILED／CANCELLED／MEDIA_READY 不能 cancel。恢复不清预算、原截止或已发生费用，不是重新批准入口。

操作状态主要为 RESERVED／SENDING／UNKNOWN／WAITING_EXTERNAL／REMOTE_READY／SUCCEEDED／FAILED。REMOTE_READY 只表示远程结果可取回，尚未证明本地文件校验成功。providerJobId 只展示／排查，不供客户端另构查询请求；后台始终查询已保存原 ID。UNKNOWN／未知费用不显示零成本，不自动换 API 或重新购买。

#### PPT 请求与交付

```json
{
  "taskType": "NOTES_PPT",
  "remarks": "整理为课堂讲义",
  "documentIds": [101, 102],
  "strategy": "FIXED",
  "presentationOptions": {"pageCount": 0, "themeId": "default", "maximumAmount": 20, "imagePolicy": "MIXED"}
}
```

pageCount=0 为自动模式，显式总页数为 2～512，包含动态来源页；实际内容单位数与页数读取 contentPlan，不能固定减一。主题仅 default。imagePolicy 为 MIXED／CONCEPT／FACTUAL，省略默认 MIXED。maximumAmount 为正数、最多 8 位小数且不超过 30，仍受服务端累计费用守卫约束；不得发送旧规划中的 slideCount、audience、language 等字段。批准前核对字体、版式和最多 8 张配图。事实图必须保存可核验出处，不能用生成图替代真实对象／时期；`MEDIA_FACT_IMAGE_REVIEW_REQUIRED` 表示尚需核验。

PPT 固定使用资料内容计划，`GET /media-plans` 返回 []；content-plan 返回已接受的内容计划。预览 planVersion 是内容计划版本，previewVersion 是编辑／审批版本，二者不可互换。预览必须携带 contentPlan，编辑不得改变目标数量、ID 顺序或配图方式。

批准后获取素材、实际导出并登记候选。presentation-export 只重建当前已批准输入的本地文件，不更改购买批准或延长期限。

通过 `/presentation-check` 获取当前版 PresentationBundle，204 不使用旧版检查缓存。`artifactId` 用于 PPTX 下载，`pages[].artifactId` 用于 PNG 预览；file.storageKey 是存储标识，不能当公开 URL。结构 PASSED 与质量 REQUIRES_HUMAN_REVIEW 是自动检查事实，人工状态读取任务，不自动改写检查字段。逐页 PNG 用 Bearer 获取 Blob 展示，退出、拒绝、取消、来源撤销或预览编辑后撤销 Blob URL。

制作阶段包括 PPT_EXPORTING／PPT_CHECKING／PPT_WAITING_REVIEW，以实际 progress.stage 为准。PPTX 中文正文、形状与讲者备注可编辑，图片按原比例嵌入，PNG 用于预览。下载 MIME 为 `application/vnd.openxmlformats-officedocument.presentationml.presentation`，响应含 `.pptx` 文件名、Content-Length、X-Artifact-Checksum（SHA-256）、X-Artifact-Revision、nosniff／no-store。产物下载使用 artifactId，不使用 taskId。

### 6.10 视频能力、分镜和交付

先查询 `/media/video-capabilities` 和 `/media/catalogs`，用实际启用人物／声音／场景 ID 创建。能力候选缺失、报价未核验或视频运行时不可用时，前端提示后端配置，不展示可生成承诺。目录的提示映射不保证绝对一致的外观或音色。

下面 characterId／voiceId／sceneId 必须替换为目录返回值，预算仅为示例：

```json
{
  "taskType": "NOTES_VIDEO",
  "topic": "解释水循环中的凝结过程",
  "documentIds": [101],
  "strategy": "PLANNED",
  "videoOptions": {"characterId": "replace-with-catalog-id", "voiceId": "replace-with-voice-id", "sceneId": "replace-with-scene-id", "seconds": 15, "maximumAmount": 20, "shotCount": 3, "burnSubtitles": false}
}
```

seconds 为目标总时长 1～90 秒，还受镜头数与已核验时长档位共同上限约束。shotCount 为 1～6、省略默认 3；burnSubtitles 省略默认 false，SRT 独立保存。maximumAmount 与 PPT 相同。不要传旧规划字段 durationSeconds、language 或外部模型地址。

Storyboard.shots[].video 保存已批准的能力配置快照及 resolution／audioMode／seconds／reason。用户修改选择时 PATCH video-selection，shots 必须完整覆盖原单位顺序，shotId 对应 unitId；profileId 取能力 id，规格／秒数取其允许值，reason 非空白且最多 1000。服务端补齐能力快照和价格，不接收客户端报价。同一整片所有镜头必须使用同一个 API 及配置版本，混用报 MEDIA_SINGLE_VIDEO_API_REQUIRED。

audioMode 仅 NATIVE（视频 API 原生声音）或 NONE（无声）；分别映射提供方 audio=true／false。NONE 时台词必须为空，否则 MEDIA_AUDIO_REQUIRED。返回音轨与批准参数不一致报 MEDIA_AUDIO_MISMATCH；有音轨不证明台词完整、口型同步或风格一致，仍需本人听验。独立 TTS 已移除，前端不调用音频生成接口。

media-progress 中 audioDurationMs 为 null 表示未测、0 表示确认无音轨、正数表示实际音轨时长；timelineStartMs／timelineEndMs 为实测毫秒时间轴。totalShots／completedShots 只计镜头素材，不能换算整片发布成功。后台取回原视频后由 JavaCV 检测、拼接和可选字幕烧录；单镜头无需烧录可复用原视频。

WAITING_MEDIA_REVIEW 时按 task.artifactId 下载候选 MP4；独立 SRT 等其他已登记附件由 preview.assets[].artifactId 获取，只使用非 null 的真实 ID。实际时长超批准范围返回 MEDIA_REAPPROVAL_REQUIRED，未知提交、字幕／拼接／预算失败不得自动重新购买。真实视频质量、事实配图与模型全链路的已验范围见验收报告，本轮文档核对不扩大验收结论。

## 7. SSE 协议与可复制客户端示例

`POST /chat/stream` 使用带 Bearer 的 fetch 读取流。原生 EventSource 不适用于当前 POST＋认证头协议；没有 GET 订阅、Last-Event-ID 续传或自动重连去重能力。

当前服务同步核验身份、参数、会话归属和已知版本，然后先发送无正文 `progress {stage:processing}`。问答在有界执行器生成期间每两秒重复该无正文处理心跳；它用于连接存活与断线检测，不代表模型供应商的具体阶段。全文完成、汇聚和发布授权复核后才发送 validated／delta／citation／done。delta 为已校验全文的分段输出，每段最多 512 个 UTF-16 单元，**不是模型原生 Token 流**。

| 事件（event） | 数据（data） | 客户端行为 |
|---|---|---|
| progress | `{"stage":"processing"}` 或 `{"stage":"validated"}` | processing 仅显示处理中；validated 表示服务端完成后端校验 |
| delta | `{"text":"回答片段"}` | 追加文本 |
| citation | 一个 EvidenceBundle | 按 evidenceId 收集引用 |
| done | 完整 AiResult | 以其 answer／citations 覆盖最终结果，避免再次追加全文 |
| error | `{"code":"MODEL_INVALID_OUTPUT","message":"..."}` | 显示失败并结束；没有 done，也不保证 retryable 字段 |

事件有字符串 id，从 1 递增，但仅对本次响应有效。同步准入时鉴权、权限、参数、已知会话版本失败直接返回非 2xx JSON，SESSION_CONFLICT 为 409；异步期间的并发会话冲突、授权撤销、模型／基础设施失败返回 HTTP 200 + SSE error，且没有 done。HTTP 200、收到 done 都不能单独证明传输正常结束：应等待正常 EOF；无 done 也无 error 的断流属于结果不确定，不自动重发模型请求。

容器断线回调、发送异常和超时撤销请求控制；取消先于短事务提交时不保存迟到成功问答。若合法 SQL 提交已先完成，随后 TCP 断线可能仍保存该合法答案，此事实没有传输确认含义。会话客户端应 GET 当前 version 及 messages 核对，再由用户决定是否重新提问；浏览器终止读取不能保证供应商已停止模型调用或计费。

以下代码面向当前协议，可复制到前端请求模块。所有相对路径假设同源代理已设置；token 由登录状态注入。示例不处理 UI 或令牌持久化。

```javascript
const API_BASE = "/api/v1";

async function checkResponse(response) {
  if (response.ok) return;
  let detail = {};
  try { detail = await response.json(); } catch { /* 非 JSON 代理错误 */ }
  throw Object.assign(new Error(detail.message || `HTTP ${response.status}`), {
    httpStatus: response.status, code: detail.code || "HTTP_ERROR",
    retryable: detail.retryable === true, requestId: response.headers.get("X-Request-Id")
  });
}

// JSON 接口；空正文成功返回 undefined。登录时不传 token。
async function api(path, { method = "GET", token, json, key, signal } = {}) {
  const headers = {};
  if (token) headers.Authorization = `Bearer ${token}`;
  if (json !== undefined) headers["Content-Type"] = "application/json";
  if (key) headers["Idempotency-Key"] = key;
  const response = await fetch(`${API_BASE}${path}`, {
    method, headers, signal,
    body: json === undefined ? undefined : JSON.stringify(json)
  });
  await checkResponse(response);
  const text = await response.text();
  return text ? JSON.parse(text) : undefined;
}

async function uploadDocument(file, knowledgeBaseId, token, key, signal) {
  const form = new FormData();
  form.set("knowledgeBaseId", String(knowledgeBaseId));
  const allowed = ["text/plain", "text/markdown", "text/x-markdown", "application/octet-stream"];
  const upload = allowed.includes(file.type.toLowerCase()) ? file
    : new Blob([file], { type: /\.(md|markdown)$/i.test(file.name) ? "text/markdown" : "text/plain" });
  form.set("file", upload, file.name);
  const response = await fetch(`${API_BASE}/documents`, {
    method: "POST", signal,
    headers: { Authorization: `Bearer ${token}`, "Idempotency-Key": key },
    body: form
  });
  await checkResponse(response);
  return response.json();
}

async function readChatStream(request, token, onEvent, signal) {
  const response = await fetch(`${API_BASE}/chat/stream`, {
    method: "POST", signal,
    headers: { Authorization: `Bearer ${token}`, "Content-Type": "application/json", Accept: "text/event-stream" },
    body: JSON.stringify(request)
  });
  await checkResponse(response);
  if (!response.headers.get("content-type")?.includes("text/event-stream") || !response.body) {
    throw Object.assign(new Error("没有获得 SSE 响应"), {
      httpStatus: response.status, requestId: response.headers.get("X-Request-Id")
    });
  }
  const reader = response.body.getReader();
  const decoder = new TextDecoder();
  let pending = "", result, completed = false;

  function drainFrames() {
    let boundary;
    while ((boundary = /\r?\n\r?\n/.exec(pending))) {
      const frame = pending.slice(0, boundary.index);
      pending = pending.slice(boundary.index + boundary[0].length);
      let event = "message";
      const data = [];
      for (const line of frame.split(/\r?\n/)) {
        if (line.startsWith(":")) continue;
        const colon = line.indexOf(":");
        const field = colon < 0 ? line : line.slice(0, colon);
        const value = colon < 0 ? "" : line.slice(colon + 1).replace(/^ /, "");
        if (field === "event") event = value;
        if (field === "data") data.push(value);
      }
      if (!data.length) continue;
      const payload = JSON.parse(data.join("\n"));
      if (event === "error") {
        onEvent(event, payload);
        throw Object.assign(new Error(payload.message || "问答失败"), { code: payload.code, httpStatus: response.status, requestId: response.headers.get("X-Request-Id") });
      }
      if (event === "done") { result = payload; completed = true; }
      onEvent(event, payload);
    }
  }

  try {
    while (true) {
      const { value, done } = await reader.read(); // 断流即抛错，不把已收到 done 当成正常 EOF
      if (done) break;
      pending += decoder.decode(value, { stream: true });
      drainFrames();
    }
    pending += decoder.decode();
    drainFrames();
    if (!completed || pending.trim()) throw new Error("响应未完整结束，请核对后决定是否重新提问");
    return result;
  } catch (error) {
    // 初始响应已经取得时，断流／解析错误也保留本次服务端排查编号。
    throw Object.assign(error instanceof Error ? error : new Error(String(error)), {
      httpStatus: response.status, requestId: response.headers.get("X-Request-Id")
    });
  } finally {
    await reader.cancel().catch(() => {});
    reader.releaseLock();
  }
}

// 原文传 /documents/{id}/source；学习／媒体附件传 /artifacts/{artifactId}。
// filename 可从 Content-Disposition 解析，或使用前端已知的安全文件名。
async function download(path, filename, token) {
  const response = await fetch(`${API_BASE}${path}`, {
    headers: { Authorization: `Bearer ${token}` }
  });
  await checkResponse(response);
  const url = URL.createObjectURL(await response.blob());
  const anchor = document.createElement("a");
  anchor.href = url; anchor.download = filename;
  document.body.append(anchor); anchor.click(); anchor.remove();
  setTimeout(() => URL.revokeObjectURL(url), 1000);
}
```

调用 SSE 时可用 AbortController 管理页面生命周期与客户端等待时限，例如设置约 90 秒的等待上限；后端在线预算为 60 秒，单次模型至多 30 秒。处理心跳不授权自动重连；用户中断阅读后按第 6.6 节核对会话已保存事实，不保证取消已发出的模型调用。

下载地址不能直接放到需要登录的 `<a href>`／iframe 中期待浏览器自动附带 Bearer，也不能把 token 加到 URL。报告预览可用同样的认证 fetch 读取 text，再安全渲染 Markdown。资料及模型文本不可信，使用 textContent 或经过净化的 Markdown 渲染，禁用原始 HTML；不要把回答直接传给 innerHTML。

原文下载的服务端附件名为 `document-{id}.txt`，报告为 `report-{taskId}.md`。原文下载是当前版本的 UTF-8 文本，上传时的 BOM 已移除，不保证与上传文件字节完全相同；前端可提供合理的下载文件名，但不能据此增加历史版本能力。

## 8. 错误处理

普通错误格式：

```json
{"code":"OPERATION_CONFLICT","message":"文档版本已变化","retryable":false}
```

| HTTP 状态 | 错误码（code） | 前端处理 |
|---|---|---|
| 401 | AUTH_REQUIRED | 登录失效／凭证错误；按第 3 节区分登录和改密场景 |
| 403 | PASSWORD_CHANGE_REQUIRED | 引导首次改密 |
| 403 | ACCESS_DENIED | 显示当前不可访问，清除相应私人内容缓存；不要自动扩大范围 |
| 400 | INVALID_ARGUMENTS | 校验参数、未知 JSON 字段、枚举、ID；保持用户输入 |
| 400 | UNSUPPORTED_DOCUMENT_TYPE、DOCUMENT_PARSE_FAILED | 格式／编码／正文问题，提示修改文件 |
| 400 或 413 | DOCUMENT_LIMIT_EXCEEDED | 大小、文本、文档／知识库／偏好配额等；查看 message，不能都解释成上传过大 |
| 409 | OPERATION_CONFLICT | 版本、同键异参、重复状态操作、用户名重复、最后管理员保护等；按操作重新查询核对 |
| 409 | SESSION_CONFLICT | 会话版本变化、执行中或读取范围变化；GET 刷新会话／消息，再由用户决定是否重新提问或删除 |
| 409 | APPROVAL_CONFLICT | 确认已处理或目标变化，重新预览／准备 |
| 409 | CONTEXT_VERSION_CONFLICT | 章节游标／恢复覆盖的版本或代次已变化；刷新当前文档和目录，禁止在新版套用旧位置 |
| 409 | INDEX_NOT_READY | 当前内容版本尚无激活结构；等待处理 |
| 409 | STALE_EXECUTION | 执行权变化；刷新服务端状态，不自动重放写操作 |
| 410 | APPROVAL_EXPIRED | 笔记重新 prepare；媒体重新核对预览／有效批准 |
| 410 | WORKFLOW_RETIRED | 旧 FAQ／研究报告已移除，仅保留历史查询，禁止自动重试 |
| 409 | WORKFLOW_RESULT_UNAVAILABLE | 学习结果未发布，先查任务状态 |
| 409 | WORKFLOW_STATE_CONFLICT、WORKFLOW_EXECUTOR_UNAVAILABLE、WORKFLOW_BINDING_MISSING、WORKFLOW_ARCHITECTURE_MISMATCH、WORKFLOW_GRAPH_INVALID、WORKFLOW_REVIEW_REJECTED | 工作流状态／保存执行版本／质检冲突，展示实际码，不换架构重跑 |
| 409 | BUDGET_EXCEEDED、INGESTION_BUDGET_EXCEEDED | 本次累计额度或期限耗尽，恢复不重置预算 |
| 409 | INGESTION_PLAN_CONFLICT、INGESTION_RECOVERY_CONFLICT、EMBEDDING_RESULT_UNKNOWN | 处理计划／恢复条件或未知发送冲突；先查 ingestion，不自动新建代次 |
| 409 | FEE_CONFLICT、FEE_SCOPE_REQUIRED、FEE_PRICE_UNAVAILABLE | 账本范围／价格无法确认，不继续付费 |
| 503 | FEE_LEDGER_UNAVAILABLE | 账本不可用，retryable=false，停止新付费请求 |
| 400 | PREVIEW_CHANGED、MEDIA_SUBMISSION_UNKNOWN、MEDIA_REAPPROVAL_REQUIRED、MEDIA_AUDIO_REQUIRED、MEDIA_AUDIO_MISMATCH、MEDIA_SINGLE_VIDEO_API_REQUIRED | 媒体预览／未知发送／规格或音轨约束；刷新并按实际码处理，不自动重购 |
| 429 | RATE_LIMITED | 登录窗口／未完成任务配额／并发等限制，退避；不假设一定带 Retry-After |
| 504 | MODEL_TIMEOUT | 提示本次未获得结果，由用户决定是否重试 |
| 503 | MODEL_UNAVAILABLE、NO_COMPATIBLE_FALLBACK、SEARCH_UNAVAILABLE | 服务／模型暂不可用，不降级展示伪造答案 |
| 503 | MEDIA_CAPABILITY_UNAVAILABLE | 当前媒体能力／规格／运行时不可用，联系后端确认，不进入付费流程 |
| 503 | ACCESS_AUDIT_UNAVAILABLE | 审计无法确认，跨库结果未交付；retryable=false，不自动重发付费请求 |
| 400 | MODEL_INVALID_OUTPUT、CONTEXT_MAPPING_INVALID | 本次结果未通过约束／预算；不是成功回答，也不应只显示“输入框错误” |
| 400／SSE error | REQUEST_CANCELLED | 请求生命周期已停止，未开始的提交已取消；先核对会话已有事实，不自动重复模型调用 |
| 400 | MODEL_ROUTE_NOT_FOUND、MODEL_CAPABILITY_MISMATCH | 后端模型配置／能力不匹配，提示联系后端检查 |
| 500 | INTERNAL_ERROR | 服务暂不可用，保留草稿，提供手动重试 |

上述是常见错误，不要求前端枚举所有未来 code。未知错误显示安全 message 与 code，不展示内部堆栈。普通错误的 retryable 表示后端类别可重试，不授权前端自动重新生成付费任务；SSE error 缺少该字段时不擅自当成 true。

学习后台还可能通过 TaskSnapshot.errorCode 返回 WORKFLOW_INPUT_TOO_LARGE／WORKFLOW_NEEDS_INPUT／CONTEXT_VERSION_CONFLICT／MODEL_CONTEXT_INSUFFICIENT／WORKFLOW_REVIEW_REJECTED／SKILL_UNAVAILABLE 等。任务查询本身可能仍为 200；该 HTTP 状态只说明读取成功，生成结果须结合 status 判断。

PPT 错误：PPT_PAGE_LIMIT／PPT_IMAGE_MISSING／PPT_IMAGE_SOURCE_REQUIRED／PPT_TEXT_OVERFLOW／PPT_IMAGE_INVALID／PPT_STRUCTURE_INVALID／PPT_EXPORT_EXHAUSTED 为 409；PPT_FONT_UNAVAILABLE／PPT_FONT_GLYPH_MISSING／PPT_EXPORT_FAILED 为 503；PPT_EXPORT_TIMEOUT 为 504；PPT_LAYOUT_INVALID／PPT_CONTENT_INVALID／PPT_INPUT_INVALID 为 400。所有 PPT_* 的 retryable=false。图片损坏以 MEDIA_VALIDATION_FAILED 停止，不自动重新生成。

## 11. 本人运行图与检查页

`GET /api/v1/runs?page=0&size=20`、`GET /api/v1/runs/{id}`、`GET /api/v1/runs/{id}/graph`均Bearer认证、本人所有权、`Cache-Control: no-store`。ADMIN也不能读取他人私人记录；匿名401、他人ID403、图ID格式错误400。旧运行无节点仍可查询，但标为不完整。运行摘要不含正文；图中内容快照读取前复核来源及其递归依赖，来源撤销时隐藏内容并保留状态和时间。禁用／权限版本变化按当前身份拒绝。

TraceSnapshot保留traceId／actorUserId／status／modelId／attempts／mock／createdAt，追加endedAt、sessionId、taskId、ingestionId、previousTraceId、incomplete、telemetryDropped、nodeCount、firstDeliverableAt。关联字段与时间可为null。任务／同代次入库每次领取新trace，previousTraceId是同所有者同逻辑任务的上一执行，旧记录过保留期后可能不可访问。恢复成功结果显示REUSED，不补造一次模型调用。

TraceGraph形状为 `{run,nodes,edges,missingNodeIds,incomplete,costStatus:"UNKNOWN"}`。节点字段：spanId／parentSpanId、type／name、stepId／agentId、dependsOn（实际spanId[]）、sequence、status、startedAt／endedAt、errorCode、modelId／taskType／profile／policyVersion／routeReason／attempt、inputTokens／outputTokens／usageSource、toolCallHash。时间是UTC ISO-8601；durationMs由endedAt-startedAt计算，未结束为未知。sequence是登记序号，不能当作并行执行顺序。MODEL和EMBEDDING叶节点记录用量；父角色／工具／根节点没有计费用量，禁止重复相加，UNKNOWN不能当零费用，SIMULATED不算真实用量。

边为 `{from,to,kind:"CALL"|"DEPENDENCY"}`。CALL仅表示嵌套，DEPENDENCY来自角色调度与工具申请／续轮的实际关系。工具申请和执行用toolCallHash配对，不回传原callId。依赖可指向缺失节点；missingNodeIds、未结束节点、行数不符、旧摘要、限量截断、等待写入、队列／DB／导出故障都会使graph.incomplete=true。图来自真实程序记录，不返回预设五步图冒充执行；历史报告计划可按本人权限只读查询；当前学习工作流不生成该计划。

检查页 `/run-inspector.html`（配套JS／CSS）是可匿名访问的空壳；输入本人账号登录后查询私人API，token仅在页面内存，退出清空数据。提供本人最近50条、节点树（parentSpanId）、实际时间线、调用／依赖连线和上一执行跳转。所有动态值使用textContent，禁止innerHTML、脚本执行、Mermaid正文拼接或URL令牌。手动刷新，运行中只有不完整控制摘要，执行结束后异步写入节点；页面显示服务器首次放行时间，不能解释为浏览器已收到。模型真实TTFT当前不可用，保持未知；模型节点endedAt是模型调用结束时间。

节点详情新增 `input`／`output`，形状为 `{content,truncated,originalChars}`；字符数按Java／JavaScript字符串长度计，表示过滤后的内容。当前资料工作流（自测、整编、资料PPT）与绑定来源的视频角色采集工作节点输入、结构化输出、REUSED结果，以及其模型／工具调用内容。未绑定来源的普通聊天、入库和其他未接入节点仍只有元数据。每侧最多16,384字符，每运行最多524,288字符，超长明确标记truncated，预算耗尽后的内容不记录。快照不是完整产物下载；过滤凭证字段、常见认证文本及签名参数，不保存配置对象或原始HTTP响应，不进入普通日志／外部OTLP。沿用ai_spans.node_json和现有观测保留期，无需数据库迁移。

独立产品前端 `Novid-frontend` 点击节点后打开详情抽屉，集中展示状态、开始／结束、耗时、节点输入和节点输出；Token用量单独注明。简易检查页也支持点击及Enter／Space操作。旧JSON缺少字段或为null表示未记录，不补造内容；input／output均null但payloadSources非空表示读取时隐藏了内容。失败节点可能保留已收到的模型输出，但状态及errorCode仍决定结果是否通过校验。图节点仍在本次执行结束后异步写入，不提供逐节点实时快照推送。

## 12. 费用显示与未知成本

以下接口已实现，均为Bearer认证、200 JSON、`Cache-Control: no-store`。普通USER和ADMIN的私人费用查询都只限本人；管理员仅可读无私人标识的聚合。客户端不能提交价格、用量、退款、操作键、身份或增大预算。

| 方法 | 路径 | 范围 |
|---|---|---|
| GET | `/api/v1/runs/{traceId}/fees` | 本次运行的独立叶子尝试；观测删除后，只要账本仍存在仍可查询 |
| GET | `/api/v1/tasks/{taskId}/fees` | 本人任务跨领取／恢复的全部尝试 |
| GET | `/api/v1/ingestions/{ingestionId}/fees` | 本人指定入库代次全部批次；ingestionId取文档ingestion响应，不是documentId |
| GET | `/api/v1/admin/fees?days=7` | ADMIN最近1～30天的币种聚合数组，不含userId／taskId／operationId或正文 |

FeeSummary字段：`kind/resourceId/currency/limitAmount`、`estimatedAmount/reservedAmount`、`providerInputTokens/providerOutputTokens/reservedTokens`、`attempts/settledAttempts/unknownAttempts/pendingAttempts/simulatedAttempts/legacyUntrackedAttempts`、`overLimit/costStatus`。金额是八位十进制小计；前端显示金额时不要做浮点累加。`currency`是服务端预算币种，缺报价时不证明供应商账单币种。`limitAmount`是首次范围创建的服务端上限，运行为后台资源的一个子集时该上限仍属于整个后台范围。

`SETTLED`表示程序已用固定价格快照与提供方用量完成计算，`estimatedAmount`仍为ESTIMATED，**不是供应商账单实付金额**。`reservedAmount`是RESERVED／SENDING／UNKNOWN中已报价的预留小计；缺价格的预留没有可计算金额，不能从这个小计推断未知成本为零。提供方词元小计可含未知费用尝试的部分已知用量；`reservedTokens`是未定价结算尝试保守预留，不能再与提供方小计相加冒充实际总量。模拟不进入真实用量或金额小计。`attempts`含可靠意图（包括明确未发送后释放的意图），与模型实际发送次数不能直接等同。

`costStatus`为UNKNOWN（未知／未结算／旧缺账至少一种）、ESTIMATED（全部真实记录已按快照计价）、SIMULATED（只有模拟）或NO_RECORDED_ATTEMPTS（没有记录到尝试）。旧运行、任务及代次已有调用但无可靠账本记录时，`legacyUntrackedAttempts>0`且UNKNOWN，不补造历史金额。无记录也不证明未来免费。运行图的旧`costStatus:"UNKNOWN"`仍表示图不是账本；检查页独立读取fees接口，费用不可用不会阻断图显示。

FeeAggregate字段为`currency/attempts/unknownAttempts/pendingAttempts/simulatedAttempts/estimatedAmount/reservedAmount`；所有数字只是窗口内已记录部分。匿名401、他人或撤销身份403、非法标识／days400。新增`FEE_CONFLICT/FEE_SCOPE_REQUIRED/FEE_PRICE_UNAVAILABLE/BUDGET_EXCEEDED`为409，`FEE_LEDGER_UNAVAILABLE`为503且`retryable=false`。可靠账本失效停止新付费请求，不能因503自动重发chat或恢复任务；先核对原运行／任务。取消不代表远程停止或退款，UNKNOWN不提供安全重购按钮。没有公开对账／退款写 API 或媒体回调接口；媒体审批及 PPT 接口见第 4.6 节。

## 13. 管理审计、指标与缓存

`GET /api/v1/admin/access-audit?afterId=0&size=20` 返回递增ID的下一页，size为1～100，afterId非负。取本页最后id作为下一页游标；空数组表示本次没有后续记录，不承诺永久保留。`GET /api/v1/admin/metrics?days=7` 接收1～30天窗口。两者均Bearer认证、当前ADMIN、200 JSON／no-store；匿名401、USER／旧ADMIN／禁用账户403，非法参数400。没有管理清理写API。

AccessAudit字段为 `id/actorUserId/action/resourceId/scopeMode/permissionVersion/knowledgeEpoch/resultCount/outcome/createdAt/knowledgeBaseIds/ownerUserId/resourceIds`。后三项为受信SELECTED库集合、缩小范围的owner筛选、结果对象ID集合；SELECTED以外的库集合为空，ALL由纪元和筛选描述。resourceIds最多100项，仅ID；列表是库／文档ID，SEARCH／SEARCH_CACHE_HIT是召回文档ID，READ_BASE／READ_DOCUMENT是直接对象，STATISTICS没有单个返回对象。检索resultCount是候选片数，不是最终引用数。旧行缺字段保持null，不能说成完整审计。

动作包括 `LIST_BASES/LIST_DOCUMENTS/READ_BASE/READ_DOCUMENT/STATISTICS/SEARCH/SEARCH_CACHE_HIT`；目录、小片及原文下载也经过文档读取审计。管理员SELF也记录；普通USER不会写管理员跨库审计。outcome=DELIVERABLE表示服务端完成当前复核且同步审计可确认，**不证明浏览器已收到**，不代替最终发布／引用复核。无权候选被过滤；该表记录可交付读取，不是所有被拒绝的恶意尝试或完整网络安全日志。审计失败为503 ACCESS_AUDIT_UNAVAILABLE、retryable=false，受影响结果不交付；不能绕过审计展示缓存旧正文。

OperationalMetrics字段为 `runs/failedRuns/incompleteRuns/queuedTasks/pendingOutbox/accessEvents/queryCacheHits/queryCacheMisses/queryCacheEntries`，只有计数，无用户／运行ID、问题、正文或工具参数。前三项和accessEvents按days窗口；失败运行是status非SUCCESS／RUNNING的排错记录，包括取消／失败，不能等同HTTP错误率。排队任务与PENDING／PROCESSING Outbox是当前积压；缓存命中／未命中从本实例启动累计，键数近似，重启归零。它不是全实例指标看板、延迟分位数或账单；费用独立GET /admin/fees，UNKNOWN不能当免费。

服务端只缓存最多40项检索候选ID及精确文档版本／处理代次，60秒／512键；不缓存答案、正文、父段／邻片、偏好或会话。键包含当前身份／角色／permissionVersion、完整Scope／筛选、SELF／SELECTED至多100库的版本摘要、全局内容／处理纪元、问题和向量hash、检索参数／固定无提示词检索策略／索引和embedding空间策略。所有Scope保守跟随knowledgeEpoch失效，ALL不枚举无限库。命中仍重核身份／纪元，再由MySQL复核所有实际included原文／版本／代次／来源，模型发送和交付沿用原守卫；召回中纪元变化返回409 CONTEXT_VERSION_CONFLICT。偏好和私人摘要实时读取，删除后窗口重置，不共享管理员ALL结果给USER。命中只节省ES两路召回，当前每次问答仍可能发生embedding／chat并正常计费，不能显示“缓存免付费”。

登录保持规范化账号五分钟最多五次请求；容量满拒绝新名称，不淘汰有效限流事实，只保存账号hash。密码验证最多四个并发许可，超限429。限流为单实例内存策略，重启归零，不声称跨实例共享或生产抗攻击容量已验证。前端不假定一定有Retry-After，不自动反复登录。

工作流架构由服务端声明式登记，客户端继续使用既有资料备注和视频参数协议，不新增自由架构选择。任务创建即保存绑定；恢复遇到绑定缺失或失效须展示实际错误，不能通过修改 strategy 自动切换架构。独立架构的接入约定见 [AI 模块说明](../lab-ai/README.md)。
