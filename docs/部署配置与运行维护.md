## 构建与本地启动

需要 Java 17。Maven Wrapper 固定 3.9.11；本机 Wrapper 下载时遇到系统 TLS 问题，已用 Python 下载官方发行 ZIP 并核对官方 SHA-512 后预热本地缓存。普通 Maven 3.9.x 也可用于构建。

```powershell
# 本机可选：让 Wrapper 缓存在项目 var 下，避免改动共享 Maven 配置
$env:MAVEN_USER_HOME = Join-Path (Get-Location) 'var/maven-home'
.\mvnw.cmd verify
# 如当前机器未预热缓存且 Wrapper 下载受 TLS 环境影响：
mvn verify
java -jar lab-demo/target/lab-demo-0.1.0-SNAPSHOT.jar
```

CLI 精确断言 Markdown 代码内标题不建章节，以及 Mock 主超时切备用两次尝试；输出明确带 Mock。不会调用付费模型／TTS。

真实存储集成仅在显式 profile 中启用：

```powershell
.\mvnw.cmd -Pintegration clean verify
```

MySQL 容器集成用例固定 `mysql:8.4.12`。Docker 不可用则记录为跳过，不以其他数据库替代验证。当前执行范围和结果见[测试验证与验收报告](测试验证与验收报告.md)。

## 环境文件与 IDEA 配置

Compose 仅启动 MySQL 8.4.12 和 ES 8.15.0。端口只绑定本机；关闭 ES 安全仅用于这份本地学习配置。外部 ES 支持 ES_USERNAME／ES_PASSWORD 成对配置，使用 Basic 认证；按用户要求，application.yml 的 trust-all 默认值为 `${ES_TRUST_ALL:true}`；当前测试 .env 显式设置 true，仅 ES 客户端跳过证书链和主机名校验。设置 ES_TRUST_ALL=false 后恢复验证，可通过 ES_CA_CERTIFICATE 指定可信 CA。凭证不要放入 ES_URL。

1. 复制 `.env.example` 为 `.env` 并填写**本项目专用**连接与凭证。
2. 如使用容器，设置 MYSQL_ROOT_PASSWORD／MYSQL_PASSWORD 后运行 `docker compose up -d`。
3. `LabApplication` 启动时自动读取工作目录下的 UTF-8 `.env`，IDEA 工作目录设为项目根目录即可。各配置项均有中文注释；值按字面填写，不加引号、不写行内注释。缺少文件时使用已有环境配置，格式错误则按行号停止启动，不输出敏感内容。显式环境变量、JVM 参数及启动参数优先于 `.env`；IDEA 中遗留的同名环境变量会覆盖文件值，若希望集中使用 `.env`，请移除对应的重复环境变量。修改配置后重启生效。
4. 首次空库初始化设置 BOOTSTRAP_ENABLED=true、BOOTSTRAP_USERNAME 和强 BOOTSTRAP_PASSWORD。已有用户时拒绝 bootstrap。首次成功后将 BOOTSTRAP_ENABLED 改为 false。
5. 构建后运行 `powershell -File scripts/start-api.ps1` 或 `java -jar lab-app/target/lab-app-0.1.0-SNAPSHOT.jar`。

DB_URL 例如 `jdbc:mysql://localhost:3306/ailab?connectionTimeZone=UTC&forceConnectionTimeZoneToSession=true`；DB_USERNAME／DB_PASSWORD 对应该专用库。Flyway 自动创建结构，不删除已有表、不自动导入教学用户。**不要连接未经明确指定的现有业务库**。

已执行的迁移文件必须保持原样，批量格式化时也应排除 `lab-data/src/main/resources/db/migration` 中的这些文件。修改缩进或空格也可能导致 `Migration checksum mismatch`，使启动校验失败。S01 已追加 V5，S02 追加 `V6__structure_mapping_and_coverage.sql`，S03追加且验收应用 `V7__durable_ingestion_batches.sql`，后续数据库结构调整从 `V8__说明.sql` 继续；遇到校验和不一致，先核对并恢复已执行版本的内容，不要直接关闭校验或运行 repair 掩盖差异。

SEARCH_ENABLED=false 时资料 CRUD 可独立运行，问答会明确返回 SEARCH_UNAVAILABLE；原文上传保持 RECEIVED，不冒称索引成功。启用搜索后，先完成受控初始化：

```powershell
powershell -File scripts/init-index.ps1
```

上面的初始化脚本只调用显式 app 参数，已存在索引不销毁。索引初始化不会自动调用付费模型。随后同时设置 SEARCH_ENABLED=true、INGESTION_WORKER_ENABLED=true，启用有两个处理线程的有界入库 Worker。报告队列另由 TASK_WORKER_ENABLED 控制。搜索业务与 Actuator 健康检查共享 `lab.search` 的地址、Basic 凭证和 TLS 配置；搜索关闭时不会创建默认 ES 健康连接。入库模型预算有上限；实际费用还需补价格／金额可靠结算。

S01 新增 `V5__private_sessions.sql`，创建 sessions/messages；本机配置库已通过正式启动应用 V5，其他部署库仍需检查自己的 Flyway 记录。S02 追加 V6；后续从 V7 追加。V1～V4 保持原样，不关闭校验或运行 repair。

环境项的中文注释以[配置模板](../.env.example)为准。本地 `.env` 保存连接和凭证且被 Git 忽略。`credential-ref` 填环境变量名称，例如 `EMBEDDING_API_KEY`，而非密钥本身。加载器支持白名单中的 33 项配置，未知项、重复项、无等号等错误按行号拒绝；值可以包含等号、井号和反斜杠，但不要加引号或行内注释。

本机当前已开启入库和报告执行器；旧 IDEA 进程需要停止、重新构建并启动后才能使用新代码与配置。进度中的 `workerEnabled` 是响应实例的开关，`executionActive` 表示是否有有效执行租约，两者用途不同。

## 模型与向量配置

MODEL_MODE=mock 或 real，真实模式不自动回退 Mock。主备验证需要 primary/backup 两个不同实际目标；当前只有一个 DeepSeek 对话测试目标时，设置 MODEL_BACKUP_ENABLED=false，可先验证单模型连接，不把该验证计作主备验收。

real 必填 MODEL_EXTERNAL_DATA_ALLOWED=true、MODEL_BASE_URL、MODEL_PRIMARY_NAME、MODEL_API_KEY。启用备用还需 MODEL_BACKUP_BASE_URL、MODEL_BACKUP_NAME、MODEL_BACKUP_API_KEY。

向量模型需要 EMBEDDING_MODEL_NAME／EMBEDDING_DIMENSIONS。独立供应商可设置 EMBEDDING_BASE_URL、EMBEDDING_CREDENTIAL_REF=EMBEDDING_API_KEY 和 EMBEDDING_API_KEY；不设置时沿用对话服务地址和 MODEL_API_KEY。不要把只支持对话的模型注册为向量模型。尚无向量服务时设置 EMBEDDING_ENABLED=false、INGESTION_WORKER_ENABLED=false、TASK_WORKER_ENABLED=false，先验证数据库／ES／对话；RAG 和文档索引不能据此标为可用。客户端只能请求业务范围，不能指定真实模型、endpoint、密钥或增大预算。

Embedding 模型和维度变化必须使用新 ES_INDEX。相同维度并不代表相同向量空间。注册配置中的 configured-baseline 只代表人工配置门槛，**并不代表质量评测通过**。S04已实现受控EXACT、单探针半开及错误分类；真实双目标／完整质量、价格／可靠费用、SDK tool-call续轮仍待补。

当前向量模型代码为 `embedding-3`，实际返回 2048 维；`EMBEDDING_BASE_URL` 仅填写基础地址，不包含末尾 `/embeddings`，避免 SDK 重复追加路径。聊天的MODEL_BASE_URL／MODEL_BACKUP_BASE_URL同样只填基础地址，不包含/chat/completions。S04备用曾因路径重复404，补验已修正，最终真实样本与未验收项见验收报告。

原连接排查参考：[DeepSeek 模型列表](https://api-docs.deepseek.com/api/list-models/)、[DeepSeek 对话协议](https://api-docs.deepseek.com/api/create-chat-completion/)、[向量供应商接口定义](https://docs.bigmodel.cn/openapi/openapi.json)。模型代码及维度以实际服务和项目配置为准，探针结果仅证明所测目标的连接。

## 检索参数与运行预算

实现位置：lab-ai 的 RagProperties 与 app application.yml。500/50/100/64/2000/4000、candidate/final=6、neighborWindow=1 对应架构第 8.3 节。计数为 UTF-8 字节保守估计，供应商 tokenizer 精确校准尚待真实联调。处理 configHash 保存实际参数快照 hash。原文 offset 是 Java UTF-16 索引，切断处保证 Unicode 码点完整；S02 保存一基原始行号、blockType／blockId／partIndex 和 sourceMap，rawText 为连续原文，重复表头的 embedding 映射指向原始表头。

S02 新增 `lab.rag.retrieval-per-route=20`、`preserve-code-blocks=true`、`preserve-table-rows=true`、`include-heading-path=true`；原 minChunkTokens 校验为1～maxChunkTokens并实际影响短块合并，neighborWindow 允许0或1。每路候选可减至1～20，candidateChunks/finalEvidence 可减至1～6，parentMaxTokens 仍不得超过2000，maxEvidenceTokens 不超过4000。修改通过应用装配的 ContextPolicy 作用于真实搜索／SQL扩展，旧处理批次不自动更新，owner 明确 reprocess 生成新 revision。

解析版本 `commonmark-0.24-v2`、切片 `structure-chunk-v2`、映射 `utf16-lines-blocks-v2`；tokenizerRef 为 `UTF8_BYTE_UPPER_BOUND`，countSource 为 `ESTIMATED_UTF8_BYTES`。实际 embedding-3／聊天目标没有本项目已确认匹配的精确 tokenizer，按字节上界校验，不能把估计当提供方 usage 或价格结算。

ES 索引名、维度、embedding 模型版本为 server config；向量模型变化必须新索引，不允许混向量空间。运行参数可减少上限，不开放任意增大或模型生成 SQL。

在线 60 秒、单次模型至多 30 秒、六轮／十次模型尝试／八工具调用；逻辑 chat 最多三次尝试、最多两个候选目标。SDK 重试为 0。上下文不足安全失败，不把超长提示送较小备用；S04问答按备用窗口重装完整历史轮次与证据；摘要／报告不静默截页，不足失败。

后台 report-v1：二十分钟累计执行、三次租约恢复、十次尝试／六轮持久预算、两个角色工作线程；角色独立上下文。持久计数在提交前消费，进程崩溃窗口也不重置。S02 每页原文默认至多2800保守词元（随 maxEvidenceTokens 减少），研究摘要至多600 UTF-8字节，汇聚至多4000；最多四个研究页给分析和汇总预留两轮，六文档时因工具边界至多一页。预算不足有明确 PARTIAL 和剩余范围，不自动扩大预算。

入库：32项／16000保守Token单批、5000小片；单代次累计160次实际尝试、2500000保守输入预留、三次领取，首次领取确定十分钟绝对期限（含等待／停机）。MySQL逐批保存计划、向量、索引事实和用量；SDK不重试。recover不清预算；retry/reprocess明确创建新revision，可能再次收费，不改原文版本。

密码 BCrypt cost=12，12～64 字符且不超过 72 UTF-8 字节。随机 token 256 位、八小时、哈希持久化。临时密码须首次修改。数据库 UTC。

索引初始化 `--lab.command=init-index` 只受控创建，已有索引保留；应禁用 Worker 与 bootstrap 并以非 Web 方式运行，scripts/init-index.ps1 已传这些参数。

## 会话运行与索引维护

### S01 会话运行与恢复

会话无需新增环境变量或凭证。重新构建并由用户重启正式后端后自动执行 V5；已有用户、偏好、文档、任务和原 ES 索引保留。会话数据和来源存 MySQL，备份应覆盖 sessions/messages，不能用 SDK 内存窗口替代完整历史。

固定硬限额：每人 100 个未删会话，每会话 10000 条消息；答案最多 65536 UTF-8 字节；模型窗口最多 12 条完整事件／8000 UTF-8 字节，摘要最多 2000 字节，单批摘要输入最多 12000 字节／64 条候选事件。摘要使用在线问答的同一 60 秒／六轮／十次尝试预算；计数为保守上界，不当作真实词元或费用。

领取执行权采用数据库时间的 75 秒租约及 UUID fencing；不会持数据库锁等待模型。成功或失败释放推进 version。进程中断后租约到期可重新取得执行权，旧执行者不能提交；不自动重放付费请求。完整成功问答在一个事务中保存，失败、超时和已观测的 SSE 断线不保存新草稿。

SSE 使用 4 个线程、8 个等待位的有界执行器及单心跳调度器，每 2 秒发送不含正文的处理进度。关闭应用时释放这些线程。取消信号阻止尚未开始的本地提交，不承诺提供方已停止计算或计费。网络断线与已开始的短事务按本地顺序决定；客户端应查会话版本和历史核验结果。

范围切换清除摘要并推进模型上下文起点。偏好新增、更正、删除会在原短事务中同步重置本人所有会话窗口、清摘要、增加版本和清执行权。会话删除清消息和摘要，保留删除元数据与至少七天 SESSION_CREATE 去重事实，同键不能复活已删内容；目前没有自动保留清理作业。

S01 专项入口为 `pwsh -File scripts/validate-sessions.ps1`。该脚本关闭首次初始化及两个 Worker 自动扫描，使用唯一本次合成资料、隔离 ES 索引与精确 ID 清理；不运行要求空库的旧全量脚本。实际执行、清理核验及未验证项见[验收报告](测试验证与验收报告.md)。

### S02 映射与章节覆盖运行

重建并由用户重启正式服务后执行追加 V6，备份新增 task_document_coverage、task_document_pages 和 chunks／document_ingestions 新字段。V1～V5 不改，不关闭校验或 repair。没有新增密钥、外部中间件或 Maven 模块，保留原 ES 严格映射；新块映射保存在 SQL，ES 仍只索引兼容的小片文本／元数据。旧批次保留 LEGACY／空版本，不自动读取用户资料重处理。

章节与扩展使用 global→user 的短授权事务；远程模型／ES 调用在事务外。页检查点主键 (task_id,document_id,page_index)，覆盖主键 (task_id,document_id)，同事务检查当前任务租约／fencing、文档版本／active revision、来源、连续页次与原文，然后 CAS 推进游标；同页异参冲突，恢复不清轮数／尝试。新代次激活后旧游标409，不能把历史引用高亮到新版。报告覆盖读取以目录正文边界推进，非检索 Top-k；未 READY 返回 INDEX_NOT_READY。

专项：`pwsh -File scripts/validate-structure.ps1`，会小预算调用真实聊天与 embedding，只用新随机合成资料与独立索引，关闭 bootstrap、入库、报告及维护扫描；优先随机库，无建库权限时按本次确定 ID 清理。任务／入库执行权由夹具按已知 ID 注入，不是正式 claim／跨进程强杀证明。`-Focused`只补SQL／HTTP失败矩阵，不重复真实聊天，仍调用embedding；完整脚本目前包含全量及新增失败断言，已有验收数字对应实际执行记录，不预宣称下一次运行数量。证据在 `var/stage-S02/`，结果及限制见[验收报告](测试验证与验收报告.md)。

### 原有索引维护

初始化使用 `scripts/init-index.ps1`，已有索引保留。文档或知识库删除、旧处理代次激活后登记清理意图；自动消费沿用 `INGESTION_WORKER_ENABLED`，该开关关闭时需受控运行维护命令：

```powershell
powershell -File scripts/cleanup-index.ps1 -MaxBatches 20
```

维护入口关闭首次管理员初始化及入库、报告自动扫描，只消费清理事件，不调用模型，也不删除整个索引。每批最多删除 256 项，达到指定批次数后退出；余下事件保留。远程异常返回非零，事件不标记完成；必须刷新并确认目标计数归零后才置 `DONE`。失败延迟重试三次后保留 `FAILED`，由运维确认故障解除再针对事件恢复。清理使用固定文档／库／旧代次边界及执行权校验，迟到执行者不能置为完成。

## 常见故障排查

| 现象 | 检查与处理 |
|---|---|
| 上传后长期 `RECEIVED` | 核对搜索、向量和入库执行器开关及索引初始化；已删除的库必须跳过，不恢复它来触发入库 |
| 健康检查连接本机 9200 | 当前代码应使用共享的 `lab.search` 连接；重新构建和重启旧进程，核对环境变量是否覆盖文件 |
| 报告长期排队 | 查看 `progress.stage`、`workerEnabled` 和 `executionActive`；关闭执行器时是 `WAITING_FOR_WORKER`，过期租约是 `WAITING_FOR_RECOVERY` |
| IDEA 与脚本启动配置不同 | 工作目录设为项目根目录；移除覆盖文件的重复环境变量，再重启 |
| 向量接口出现 401／404／400 | 分别核对凭证变量名、基础地址是否重复含路径、模型代码与维度 |
| 数据库迁移校验和不一致 | 核对并恢复已执行迁移内容；不要通过关闭校验或直接修复历史记录掩盖差异 |
| 删除后 ES 仍有旧片段 | SQL 授权已先阻止交付；检查清理事件及入库执行器，或使用有界维护命令 |

## 恢复与取消边界

正常暂停和恢复不消耗异常租约恢复次数；异常恢复最多三次，保留累计尝试、轮数和二十分钟执行期限。恢复跳过已成功检查点，并合并其真实历史来源版本和有限覆盖标志。暂停、取消立即撤销本地提交权，旧执行者不能保存新检查点或发布，但已提交的远程模型请求可能继续计费。

入库仅激活当前内容对应的最新处理意图；SQL 删除、禁用或来源撤销立即阻止读取，即使 ES 清理尚未消费。S03已持久逐批向量、累计尝试／输入和恢复，费用价格结算尚未实现。过期登录／去重／历史结构的保留清理、访问审计查询、来源限制状态标注以及完整媒体恢复也仍待完善。

跨进程终止与恢复、真实 ES 停机／部分批量写入／迟到写入、备份恢复演练与恢复时间尚未验收；测试入口和已验证范围统一见[测试验证与验收报告](测试验证与验收报告.md)。
