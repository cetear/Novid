## 原始复现事实

以下保留修复前的复现、原因和建议，供回归与追溯；其中“未实现”“建议”“验收失败”等描述属于发现当时，**不是当前状态**。当前关闭依据见上表和[验收报告](测试验证与验收报告.md)。历史源码定位仅保留文件，不以旧行号指向已经修改的代码。

### 历史发现 1：首次 MySQL 迁移和文档插入不能执行（P1）

V1 中 `documents.generated` 未引用，MySQL 8.4 返回 1064。只读连接与 Flyway info 无法发现这个建表错误；此前容器测试被跳过，因此已有 34 项测试仍全部通过。

修复：在 [V1 迁移](D:/AICodeProject/Novid/lab-data/src/main/resources/db/migration/V1__identity_knowledge_and_private_resources.sql) 和 [文档插入](D:/AICodeProject/Novid/lab-data/src/main/java/com/example/ailab/data/repository/DocumentSqlRepository.java) 中引用该列。真实 V1～V3 迁移、普通文档上传和确认生成笔记均通过。

`GENERATED` 是保留字，引用标识符是 MySQL 官方规定的处理方式。[MySQL 8.4 保留字说明](https://dev.mysql.com/doc/refman/8.4/en/keywords.html)

本次目标库没有成功应用过旧版 V1，因此修改这份初始迁移没有覆盖已成功迁移的数据。已经成功使用旧迁移的其他环境，应另行检查校验和与升级方案。

### 历史发现 2：报告恢复后丢失实际使用的旧版本来源（P1）

位置：[ReportTaskWorker](D:/AICodeProject/Novid/lab-ai/src/main/java/com/example/ailab/ai/orchestration/worker/ReportTaskWorker.java)。

复现：持久化基于文档 v1 的 research 检查点 → 将文档修订为 v2 → 暂停／恢复 → 使用真实模型完成 analysis／report。任务成功，最终产物的来源列表却只有 **v2**，没有实际使用的 **v1**。

原因：恢复读取 `done` 后重新从当前文档构建 `sources`，但复用的 `r.content()` 和 `a.content()` 仍可能属于旧版本；汇总调用只传新构建的来源和 partial 标志，没有合并检查点的真实依赖及覆盖状态。这破坏历史引用和后续来源复核，不能把成功终态作为报告来源正确的证明。

建议：检查点记录不可变输入版本和实际覆盖；汇总合并所有使用的检查点来源并重新授权，保留历史版本或显式终止不兼容恢复；partial 也从实际使用的检查点汇总。不要只修改最终报告的版本标签。

### 历史发现 3：正常暂停／恢复三次后任务永久停在 QUEUED（P1）

位置：[TaskRepository](D:/AICodeProject/Novid/lab-data/src/main/java/com/example/ailab/data/repository/TaskRepository.java)。

复现：连续执行三次领取、pause、resume，未消费模型预算。第三次恢复返回 QUEUED，第四次领取却永远得不到该任务。

原因：每次领取都增加 `attempt`，领取条件为 `attempt<3`；清理超限的语句只处理 RUNNING。正常恢复也耗尽领取次数，QUEUED 超限没有终态转换。

建议：区分正常恢复与异常租约恢复计数；若预算确实禁止继续，应在 action／claim 中返回明确拒绝或转 FAILED。保留累计模型预算，避免无执行机会的 QUEUED 状态。

### 历史发现 4：模型截断被当作完整成功文本（P1）

位置：[ModelGateway](D:/AICodeProject/Novid/lab-ai/src/main/java/com/example/ailab/ai/model/ModelGateway.java)。

本机真实 HTTP 协议模拟返回有文本、`finish_reason=length` 的 Chat Completion，正式 LangChain4j 适配和 ModelGateway 仍返回成功。程序只提取 `aiMessage().text()`，没有处理结束原因；后续汇聚也无法识别截断。

建议：保留 SDK 响应的结束原因、拒绝状态和必要续轮信息；截断独立分类，按有限修复、部分交付或失败策略处理。该证据属于协议测试，不属于外部 DeepSeek 故障实测。

### 历史发现 5：SSE 事件存在，但 HTTP 传输异常结束（P1）

位置：[AssistantController.stream](D:/AICodeProject/Novid/lab-web/src/main/java/com/example/ailab/web/controller/AssistantController.java)，安全链与异步响应生命周期也需联合检查。

真实 HTTP 两次复现：统计请求不调用聊天模型，返回 HTTP 200，已收到 progress／delta／done，但 JDK HTTP 客户端最终收到 **IOException／EOFException**，chunked 传输未正常结束。不能将收到 done 等同于传输验收通过。

当前证据确认传输问题，尚未确定是异步派发、安全链还是容器响应完成路径造成，报告不把推测写作已确定原因。建议补真正走网络的 SSE 终止断言；检查同步完成 SseEmitter 的生命周期及 ASYNC／ERROR 派发，而不仅检查事件字符串。

### 历史发现 6：配置的单模型超时未生效（P2）

位置：[ModelGateway](D:/AICodeProject/Novid/lab-ai/src/main/java/com/example/ailab/ai/model/ModelGateway.java)，embedding 路径同样使用 `budget.timeout()`。

本机协议测试将 `timeoutSeconds` 设为 1，服务 1.5 秒后响应，仍被正常接受。注册表虽校验该字段，SDK 创建时却没有使用它。

建议：实际超时取模型配置、全局单次上限、剩余总期限三者最小值；chat 和 embedding 共用一致规则。

### 历史发现 7：删除／旧批次的 ES 清理尚未实现（P2）

位置：[文档删除](D:/AICodeProject/Novid/lab-data/src/main/java/com/example/ailab/data/repository/DocumentSqlRepository.java)、[知识库删除](D:/AICodeProject/Novid/lab-data/src/main/java/com/example/ailab/data/repository/KnowledgeBaseSqlRepository.java)、ElasticsearchRepository。

删除会写 DELETE_DOCUMENT／DELETE_BASE Outbox，代码没有对应消费者和索引删除端口；重处理激活后也没有旧代次清理。验收中的 DELETE_DOCUMENT 仍为 PENDING。

当前 MySQL 最终授权／版本复核能阻止旧正文交付，这是已实现的防线；它不能替代索引清理。长期积累的无效片段仍会占用双路 Top-k，降低当前有效片段召回。

建议：完成有界、可恢复、版本化的删除／旧批次清理；只在外部结果确定后标记事件完成。补 ES 滞后条件下的召回与权限断言。

### 历史发现 8：无效列表元素返回 500（P2）

位置：[TaskController.Create](D:/AICodeProject/Novid/lab-web/src/main/java/com/example/ailab/web/controller/TaskController.java)。

`POST /tasks` 提交 `documentIds:[null]`，实际得到 HTTP 500／INTERNAL_ERROR。列表只有 NotEmpty／Size，没有元素校验；Controller 构造 TaskRequest 时 `List.copyOf` 抛异常，尚未进入业务层的 null 检查。

建议：HTTP 层使用 `List<@NotNull @Positive Long>` 等元素约束，并检查 notes 的来源列表；非法请求应在业务或持久化前稳定返回 400。

### 历史发现 9：禁用库中的本人文档无法单独删除（P2，使用行为需统一）

位置：[DocumentApplicationService.delete](D:/AICodeProject/Novid/lab-business/src/main/java/com/example/ailab/business/application/DocumentApplicationService.java)。

实测：owner 禁用自己的库后删除库中文档，得到 ACCESS_DENIED。删除先调用正文 read，而正文 read 要求库启用；数据层删除本已使用 `sql.owner(...,false)`，允许 owner 在禁用库执行删除。

同一调用结构也会使来源已撤销的本人衍生笔记难以删除。建议将删除所需的 owner／版本元数据校验与正文读取权限区分；或者明确产品要求先恢复库，并让所有层采用一致行为。

## 后续修复：文档上传与 ES 健康检查

### 原因与处理范围

用户提供的堆栈来自 Actuator 的 `ElasticsearchRestClientHealthIndicator`。业务仓库原先自行创建私有 RestClient，Spring 无法发现它，于是 ES 自动装配另外创建了默认 `localhost:9200` 客户端供健康检查使用。当前本机没有该服务，因此健康检查抛出 `Connection refused`。已配置的远程 ES 8.15.0 实际连接正常，Basic 认证与 `ES_TRUST_ALL=true` 均有效。

入库未执行还有独立的配置原因：诊断开始时 `.env` 与 IDEA 运行配置中的 `INGESTION_WORKER_ENABLED=false`，正式索引也不存在。原始数据库检查发现 14 条未删除文档记录的版本状态为 `RECEIVED`、处理尝试为 0；该状态表示已接收、尚未处理，不能据此宣称模型或 ES 写入已经失败。

进一步核对知识库状态：其中 13 条文档（ID 40～52）属于已软删除的知识库，队列必须跳过。当前有效知识库中的文档 ID 53 才是本次应处理的资料。未恢复或修改已删除知识库。

### 修复行为

## 后续改进：环境文件自动加载

根目录 `.env` 各配置项补充中文注释，示例文件同步说明。`LabApplication` 在 Spring 装配前调用 `LocalEnvironmentLoader`，读取当前工作目录中的 UTF-8 `.env`；IDEA 直接启动也可读取配置。模型和首次管理员凭证统一通过 Spring 环境解析，避免只有启动脚本生效。

解析器使用配置白名单，按第一个等号分隔并保留值的字面内容，支持 UTF-8 文件头；忽略空行和整行注释，重复项、未知项及格式错误按行号拒绝且不打印敏感值。缺少文件时使用已有配置；显式环境变量、JVM 与启动参数优先。详细配置方式仅在[部署配置与运行维护](部署配置与运行维护.md)维护。

## 后续改进：报告任务步骤与进度

原接口只返回任务状态和三个模型检查点的完成数，模型调用期间没有持久记录当前执行步骤。新增回归测试已复现：模型正在等待结果，但查询侧无法知道研究步骤已开始。另一个直接原因是本机 `.env` 与 IDEA 的 `TASK_WORKER_ENABLED=false`，任务会一直排队。

现已将报告 Worker 开关同步为 true；需要重新构建、重启 IDEA 后端进程后生效。首次登记立即返回 HTTP 202 和真实排队状态，不等待最终报告。后续每 2 秒查询 `GET /api/v1/tasks/{id}`，取得完整 `TaskSnapshot.progress`。创建返回 `Location` 和 `Retry-After: 2`，创建/查询响应禁止缓存。

本仓库没有前端页面源码；后端接口已实现，前端应读取新字段并持续轮询，不能只等待最终下载。完整类型和轮询示例已更新至 [前端开发与联调文档](前端接口与联调说明.md)。

新增 V4 迁移，在 ai_tasks 添加启动/心跳/更新时间，新增 task_step_progress。已执行的 V1～V3 不修改，现有成功检查点按实际 stepId 回填。新步骤更新也必须通过身份、租约、worker、fencing 与当前状态校验；旧执行者不能覆盖暂停、取消或恢复后的事实。

进度只对任务请求者开放，ADMIN 无私人任务旁路。响应不包含模型草稿、提示词、思维链、workerId、租约详情或密钥。Future 包装的业务异常保留 MODEL_TIMEOUT 等可信错误码，不全部退化成 TASK_FAILED。

新增 V4 迁移和五步持久进度。实际成功步骤才增加百分比，发布事务完成前最多 80%；暂停、取消、失败或租约失效均返回明确状态，终止后执行计时冻结。准备、研究、分析、汇总、发布的完整字段、状态和轮询示例统一见[前端接口与联调说明](前端接口与联调说明.md)第 6.4 节。

## 2026-10-04：S01 私有会话与多轮上下文

开发前 AiRequest 只有当前问题和范围，数据库没有会话和消息表。新增 V5、纯 Java 会话契约、本人业务用例与仓库、会话 HTTP 接口，问答增加可选的成对会话字段。完整历史按序号保存，模型窗口按完整轮次、字节和条数限制；摘要经统一模型网关生成，保留覆盖序号和全部来源。

本阶段核对并修复的边界：

| 发现 | 最终处理 |
|---|---|
| 管理员资料读取权可能被误用于私人历史 | 会话直接 ID、列表、消息、关联问答、删除都固定 actor 所有权 |
| 远程期间同会话并发、迟到结果或删除后提交 | 短事务取得 75 秒 UUID 执行权，版本 CAS 和唯一消息序号，完整问答对同事务提交；失败只释放执行权 |
| 旧摘要或历史在范围／偏好变化后继续使用 | 范围变化清摘要和派生窗口；偏好变更同事务清本人摘要、推进窗口起点、增加版本并撤销执行权 |
| 资料撤销、修订或处理代次改变后复用旧内容 | 调用模型前过滤失效完整轮次；答案提交短事务复核来源、当前范围、版本、代次、章节及原文字段 |
| 历史分页逐条授权后发生来源撤销 | 发布前短事务统一复核当前会话及可见历史事件，失败整页拒绝，不交付半页失效正文 |
| 同步 SSE 在模型等待期间发现不了断线 | 有界异步执行与两秒无正文心跳；已观测取消信号与本地提交排序，迟到模型结果不新提交 |
| 断线容器异常被通用处理器错误写成 JSON | 专门处理不可用异步响应，避免在已断开 SSE 上再次写错误 DTO |
| 在线期限可能因提交等待锁而延长 | 把同一请求截止时间传入数据提交，取得锁后及最终 CAS 再按数据库时间检查 |
| 恰好32项来源的递归扁平列表误触上限 | 先对已访问来源去重，再限制新增唯一来源；离线断言32项合法、33项拒绝 |

所有变更限定 S01；工具续轮、完整来源映射、持久费用和其他后续工作不在本次实现。没有修改环境凭证、旧迁移或已有用户资料。实际测试、真实两轮效果、临时数据清理和未覆盖竞态统一记录在[验收报告](测试验证与验收报告.md)。
