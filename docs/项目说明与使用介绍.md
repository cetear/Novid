# 项目说明与使用介绍

更新日期：2026-10-04。Novid 是多用户个人知识库与人工智能助手后端。设计依据：[项目架构文档](../AI模型应用开发学习验证项目架构.md)。本文介绍项目定位、可用功能、操作方式与固定边界；阶段状态、待办、测试基线及新会话交接统一维护在[项目开发进展](项目开发进展.md)。

## 项目用途

用户把自己的文本或 Markdown 资料上传知识库，完成索引后可以提问、查看引用和原文、确认保存生成笔记、生成常见问题集或研究报告。管理员负责创建账户，可显式跨库读取有效知识资料；修改仍只限本人，私人偏好、确认、任务、报告及运行详情不开放管理员旁路。

本仓库提供后端与前端协议说明；前端页面不在本仓库。使用浏览器页面时须通过同源代理调用后端，不能把数据库、ES 或模型凭证放到前端。

## 开始使用

1. 按[部署配置与运行维护](部署配置与运行维护.md)准备 Java 17、MySQL 8.4、ES 8.15、真实对话及向量模型；连接和凭证集中在根目录 `.env`，配置模板为[环境配置示例](../.env.example)。
2. 构建并启动 `LabApplication`。IDEA 的工作目录设为项目根目录，启动类自动读取环境文件；同名显式环境变量仍优先，修改后重启。
3. 仅在首次空系统初始化管理员；已有用户时不重复初始化。管理员创建普通账户，临时密码只返回一次；用户首次登录后先改密，再重新登录。
4. 创建本人知识库，上传 UTF-8 文本或 Markdown。上传返回 202 表示已经接收，页面等待文档处理为 `READY` 后再使用检索。
5. 新索引先受控初始化；检索和入库需启用相应开关。已删除知识库中的文档不会继续入库，不能靠恢复无效资料来验证处理。
6. 提问时选择本人或合法的指定知识库范围，查看回答与引用。管理员跨库阅读须显式选择范围；没有证据时调整问题或等待索引。
7. 需要保存人工智能笔记时，先准备内容并查看完整预览，再明确批准。准备成功不代表已保存；批准成功后使用返回的文档标识查看结果。
8. 创建常见问题集或研究报告后，立即展示排队状态，按服务端建议间隔查询五步进度。研究和分析可以同时运行；下载使用产物标识，不能把任务标识当作产物标识。
9. 暂停、恢复或取消任务应使用明确状态操作；关闭浏览器仅停止客户端等待，不等于取消后台生成。部分覆盖报告须展示覆盖说明。
10. 退出或切换账户时清理前端私人缓存。后续权限或来源变化可能使此前的引用与报告不可读，不能用旧缓存绕过授权。

完整请求、返回字段、幂等、错误、认证下载、任务轮询及推送示例仅在[前端接口与联调说明](前端接口与联调说明.md)维护。

## 业务流程与使用边界

### 账户与权限

- POST /api/v1/auth/login 返回原 token 一次；后续只用 Authorization: Bearer。服务端保存哈希，不接受 URL token。
- 管理员 POST /admin/users 创建 USER，临时密码仅返回一次。用户首次登录只能 me、password、logout；改密撤销所有旧 token。
- ADMIN 默认 SELF。ALL／SELECTED 是显式只读知识范围；修改资料仍仅 owner。
- USER 的混合合法／越权 SELECTED 整体拒绝；空 SELECTED 为零范围。
- 会话、偏好、确认、任务、产物及运行摘要均本人隔离，管理员没有私人资源旁路。
- 账户禁用、角色变更或密码变更使登录撤销，permissionVersion 更新。最后有效管理员不能禁用或降级。

### 文档入库、问答与笔记确认

POST /documents 为 multipart，一个 `file` 和 `knowledgeBaseId`，必须 Idempotency-Key。仅 UTF-8 TXT/MD/Markdown，10 MB／100 万码点／5000 小片上限，有限原文保存在 MySQL。文档／版本／入库意图／Outbox／请求去重同事务提交。新内容版本和技术处理 revision 分开。

Markdown 用 CommonMark AST 建章节；父段和小片保留原文 offset。当前计数为 UTF-8 字节的保守估计，上限含标题和重叠，不冒称供应商精确 Token。S02 保存块类型、blockId／partIndex、原始行号和检索输入到原文的精确映射；表格按行组拆，后续片重复可容纳的真实表头并记录来源。超长代码、单行与表头仍受硬额度约束，不能丢弃短尾。旧处理批次保留 LEGACY，不自动重处理用户资料。

ES 只索引小片：BM25＋kNN 各 20 候选，Java RRF；两路 scope 预过滤，MySQL 再复核当前用户／内容版本／active revision／所有来源。扩展真实父段，过大时用同章节前后一个邻片，最终最多六包、保守 4000 Token。Citation 返回 matched/included、来源版本和原文 offset。跨段表头可单独形成连续原文包，不能把不连续来源串成一个假范围。S02 章节详情按显式文档版本、处理代次和绝对 UTF-16 游标分页；只有 complete=true 才读完选定章节。最新处理错误／配置与当前激活代次通过 ingestion 查询，旧 READY 不代表新意图成功。引用支持质量还须真实固定样本评测。

不关联会话的问答保留单轮行为。以“统计”开头走真实程序统计；其他问题走授权 RAG。SSE 先发不含正文的处理进度和心跳，完整回答经汇聚／来源复核后才发送 delta/citation/done；错误不发送草稿。

### 私有会话与多轮上下文（S01）

先用 `POST /api/v1/sessions` 创建本人会话，保存返回的 id/version；提问时同时发送 sessionId/sessionVersion。成功及正常的 NEEDS_INPUT 结果会保存一对问答，返回新会话版本。后续问题可以指代先前合法历史；省略 scope 时沿用该会话当前范围。仍可不传会话字段使用旧单轮 JSON／SSE。

`GET /sessions` 分页列出本人会话，`GET /sessions/{id}/messages` 按 afterSeq 顺序恢复完整历史，服务重启后仍可读取。完整历史与模型窗口分开：模型只读取最近完整轮次和有界摘要，较长历史可能不进入当轮模型。摘要由同一模型网关生成，并记录实际覆盖序号和来源，不作为个人偏好。

另一用户和另一管理员均不能按 ID、列表、消息、关联问答或删除访问他人会话。来源禁用、删除、资料修订或权限变化后，失效历史显示 RESTRICTED，正文和来源不可读；模型也不复用失效内容。显式切换范围会清空派生窗口，保留完整历史但重新授权。更正或删除偏好也会重置派生窗口并撤销在途提交，资料和模型不能自动保存偏好。

同会话一次只允许一个请求取得执行权。版本冲突或失败后先查询最新会话版本，由用户决定是否重新提问。用当前 version 删除会话后，正文和摘要被清除；旧执行者不能恢复已删信息。SSE 已观测断线会取消尚未开始的答案提交；已完成数据库提交的合法答案仍可能存在，客户端应查询历史确认，不能把断线当作服务端未执行。

POST /notes/prepare 只是准备：绑定自有目标、目标库版本、完整文本与最多 32 个扁平来源。GET /approvals/{id} 展示预览。POST /approvals/{id}/decision 只接收 approved。有效批准在**一个 MySQL 事务**中消费确认、保存文档／来源／Outbox／operation；重复决定返回既有事实。修改目标、期限、权限或来源后不可沿用。客户端编辑笔记不能清除来源。

### 常见问题集与研究报告

POST /tasks 指定 FAQ 或 RESEARCH_REPORT、topic、scope、1～6 个 documentIds 和 header Idempotency-Key。返回 202/taskId。使用持久 MySQL 队列、180 秒租约／20 秒续租、fencing、成功检查点、持久十次尝试／六轮预算和累计二十分钟期限。

创建即返回五步进度与查询地址，`GET /tasks/{id}` 返回当前并行步骤、成功步骤比例、心跳及累计执行秒数。前端每 2 秒查询；后台执行器关闭时明确提示尚未开始，租约失效时提示等待恢复。进度只按实际成功步骤增长，发布完成前不显示 100%，详见[前端接口与联调说明](前端接口与联调说明.md)。

程序 Supervisor 以独立上下文派发 ResearchWorker（economy）和 AnalysisWorker（analysis），最多两个角色并行，再由 ReportWriter（report）汇总。角色池与协调池分离。**目前执行固定受限 DAG；不是已实现模型生成计划或 ReAct 循环。**各 profile 当前可共用目标，强/经济质量差异尚未评测。

S02 正式报告要求所选文档先完成结构入库，按目录顺序分页读取并持久保存每页摘要和范围。TaskSnapshot.coverage 登记全部所选文档，包括未读文档。最多四个研究页与分析、汇总共用六轮／十次尝试／二十分钟预算；页次上限还受八次工具边界影响，六文档时至多一个研究页。预算不足标 PARTIAL，下载列出准确未读范围，完全未读文档用普通标识列出而非正文引用，不能说任意长文全读成功。恢复复用已成功页次；版本、代次或来源变化拒绝继续。旧报告构造／检查点只保留原覆盖事实，不补假分页。暂停立即撤销本地执行权；正在远程生成的请求可能继续计费，但不能提交新结果。resume 不重置预算、不复用已成功步骤生成。终态不普通 resume。产物下载仅本人＋发布态＋当前全部来源可读。

NOTES_VIDEO 当前明确返回 MEDIA_CAPABILITY_UNAVAILABLE，表示视频能力尚未接入；PPT 创建、两类配图、预览审批与二进制导出也尚未实现。旧提示中的 TTS／模板不再是开发方案，新的同级产物规划见下节；不返回假视频或假 providerJobId。

完整请求、字段、步骤状态与轮询示例仅在[前端接口与联调说明](前端接口与联调说明.md)维护；环境开关、启动和维护入口见[部署配置与运行维护](部署配置与运行维护.md)。

## 计划功能：笔记 PPT 与教学视频（尚未实现）

PPT 与视频是两个同级入口。PPT 计划流程为选笔记／主题→生成大纲、逐页内容／备注与版式→选择配图→查看预览和费用并审批→获取图片、导出可编辑 PPTX→本人下载。概念示意和装饰图可由生图 API 生成；真实人物／事件／设备／界面等客观事实图通过搜索工具查找并核验原网页、图片出处和对象／时期，来源列入备注或来源页，找不到可靠图时明确缺图，不用生成图冒充。已付费图片中断后复用，未知结果先对账。

视频暂列 API 预留：用户选择提前登记的教学人物、配音、场景，系统结合笔记生成有来源的脚本，用户修改／审批后才调用真正的视频生成 API，最终私人下载。教学人物与账号权限、系统 Agent 各自独立；未接服务明确不可用，不采用独立 TTS 配音和本地视频合成。视频暂缺 API 不阻塞当前 PPT 阶段和核心验收。

两类生成共同使用复杂Agent架构：Planner根据任务生成受限依赖计划，Supervisor派发内容／布局或脚本／导演，配图研究根据实际搜索结果有限续轮，教学质检后最多一次局部返工；用户修改或付费素材变更需重新审批。执行步骤、等待与返工原因可见，未变的成功结果中断后复用。实际视觉／视频质量没有可用模型能力时记录人工抽查。

本节只解释目标流程，当前没有 PPT 创建／预览／二进制下载及视频目录接口。S09／S10 和 R01 的完整依赖、边界与跨会话交接统一在[项目开发进展](项目开发进展.md)，实施完成前不要按计划请求正式接口。

## 当前功能边界

上述使用介绍只描述已实现的具体路径，不表示架构所有功能都已完成。S01 已增加私有多轮会话；模型工具续轮、动态计划、可靠费用、完整运行图与笔记 PPT 按后续阶段推进，教学视频按 API 方案预留。阶段完成后同步更新本文和接口文档；计划接口未交付前不能当作可用接口调用。

## 设计取舍

- TXT/Markdown有限原文直接落MySQL，是文档明确允许的首版路径；不存在文件系统与DB伪事务。
- data 使用MyBatis-Plus读取账户PO；并发／去重／确认／任务以显式JdbcTemplate SQL落实。SQL和Mapper均不出data，未引入第二普通MyBatis Starter。
- 单应用写事务先锁 system_control，再用户/目标；教学规模以串行短写事务确保权限撤销与提交一致。远程调用永不持锁；后续优化需统一多资源锁顺序和并发验收。
- 程序固定Supervisor是实际实现；不把固定拓扑声称为模型生成计划。
- 未实现功能未用空类、假音频、假产物或假成功 API 替代。

## S03 入库逐批恢复

处理前固定批次计划与输入摘要，每批最多32项／16000保守词元。成功向量先存MySQL，随后逐批写ES；第二批失败、部分写入或写入响应丢失后，恢复按真实搜索核验补缺失项，已经生成的向量不重复付费生成。只有每批及固定版本／代次全集数量、ID、hash、原文、向量、模型和可见性都核验完成才激活。

本人通过ingestion查询最新意图的阶段、失败位置、成功／未知批次、累计尝试和用量；管理员没有他人入库管理状态旁路，原有跨库知识只读保留。同代次累计160次尝试、2500000保守输入、三次领取，首次执行十分钟绝对期限包含等待与停机。自动恢复保持预算；用户可用recover提前调度指定可恢复失败代次。retry/reprocess仍代表明确新建代次，可能再次收费，不宜前端自动循环。

向量请求已发出而结果未保存时记未知，停止自动重购；提供方没有本项目已验证的结果查询能力，不能保证远程只调用一次。迟到响应只补已知用量，不发布旧结果。已知Token、保守预留与未知费用分列，完整金额结算留待S07。全文结构仍受5000片限制，向量按单批读写；备份应包含新增向量与尝试事实。旧已成功批次不补假事实或自动重处理。

## S04 模型选项与结构化回答

问答可选服务端批准的knowledge／economy／analysis／report逻辑组选项，省略按任务选择；当前各组仍共用目标，尚无经济／分析质量差异认证。普通用户不能指定实际模型、地址、密钥或扩大预算。

可选responseFormat=STRUCTURED，让模型按固定结构生成，程序校验字段、状态和实际引用后仍返回答案正文；资料不足显示NEEDS_INPUT，非法结构最多修复一次，拒绝／截断／待工具续轮明确失败。原TEXT与会话兼容。

每逻辑调用最多两目标／三尝试，摘要、修复、主备共享在线预算。较小备用重装合法完整历史和证据；来源撤销停止发送，不拼接两模型答案或重放已完成写入。route说明选择、实际尝试与用量来源，未知不当免费；持久完整追踪和金额结算仍待后续阶段。

当前两个不同聊天目标均启用；备用因误填完整操作URL导致的404已修复，两个目标各三条真实合成样本全部通过。真实故障自动主备切换与完整profile质量仍待补验，S04状态为“实现完成、验收待补”。配置门槛和本机协议不等于完整真实主备质量通过。用户更新的.env只修正备用基础地址，密钥和其他配置、旧迁移和已有资料保留；正式服务由用户重建后重启，下一阶段等用户亲自另开会话指定。
